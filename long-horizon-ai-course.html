长程自主 AI 开发任务：让 AI 7×24 复刻一个 Photoshop

一次对话装不下的工程

复刻 Photoshop 不是"让 AI 写个程序"，而是一场持续数月的接力赛——对话式 AI 只是其中一棒。

你可能已经试过：对 AI 说"帮我写一个 Photoshop"。它会热情地给你一个 canvas + 滤镜的小玩具，几百行代码，能跑，然后呢？然后就没有然后了。

缺的不是 AI 的"智商"，而是三样东西：

  • 体量：Photoshop 真实代码量以百万行计，即使砍到教学复刻版也要数万行，需要几万次"上下文窗口"才能装下；
  • 时间：人类团队做类似规模的图像编辑器要按"年"计，AI 的强项是快，但快不等于能一口气；
  • 方向：没有验收标准和里程碑，AI 会不断"看起来在干活"，而你不知道它是在逼近目标还是原地绕圈。
把复刻 Photoshop 想成装修一栋别墅。你不能把图纸和钥匙扔给一个失忆的施工队然后消失半年——他每天早上都忘了昨天干了什么。你必须给他：分阶段的图纸、每天的验收单、写在墙上的进度标记。
四个关键词，先混个脸熟（点击翻面）
长程任务
跨越数天到数月、无法用一次模型调用完成的任务。特点是：中途会丢上下文、会出错、需要人定方向。
自主性
AI 在一段时间内不需要人逐步指挥，能自己决定下一步做什么。自主性越高，越需要可审计的检查点。
验收标准
"做到什么程度算完成"的可执行判定。好的验收标准是脚本，不是形容词。
检查点
可以随时回退和复盘的存档：Git 提交、任务状态文件、决策日志。让"失忆"变得无害。

让 AI"一句话复刻 Photoshop"失败的根本原因最接近哪个？

本章小结：长程 AI 任务的本质是工程管理问题。AI 提供"永不疲倦的手"，但图纸、验收单和进度标记得由你来设计。

7×24 的真实图景

"AI 24 小时自己干活"不是魔法全自动驾驶，而是一条有人值守的流水线：AI 全速干活，人只管三件事——方向、验收、扳道岔。

先戳破一个幻想：把任务丢给 AI，睡一觉起来收获成品。现实中，完全放养的自主 Agent 会在几个小时后开始自信地走偏：改错文件、删掉好代码、在一个死胡同里反复横跳。

目前真正跑得通的模式叫"人机分工的持久循环"：

  • AI 干的：搜索整理资料、写文档、拆解计划、写代码、跑测试、修自己能修的 bug、写日报；
  • 人干的：定里程碑和验收标准（每周）、审计划和合并大改动（每天）、处理 AI 上报的"我卡住了"（随叫随到）。

一个形象的账：假设 AI 的每个工作回合约 30 分钟，一天能跑 40+ 回合；如果每个回合有 10% 概率进入死循环，没人管的话错误会像复利一样滚大。人每天花 30 分钟审查，就能把"跑偏概率"压到极低。人的价值不是替 AI 干活，而是当"方向校准器"。

一天的 7×24 循环长什么样（点"下一步"走一遍）
02:00 · 夜班开工：AI 从任务队列领取下一个任务（如"实现亮度/对比度调整的命令类"），先读项目记忆文件（约定、目录结构、当前进度），再动手。
02:40 · 实现 + 自测：写代码 → 跑单元测试 → 测试没过就自己修，最多重试 3 次，仍失败则在任务上打"卡住了"标记，换下一个任务。
06:00 · 调研回合：遇到不熟悉的领域（如 PS 的图层合成算法），派出调研 Agent：搜索 → 筛选 → 摘要写入 docs/research/，注明出处。
08:00 · 生成日报：汇总"完成的任务 / 卡住的任务 / 决策请求"，写入 docs/reports/2026-03-12.md，附上 diff 统计。
09:00 · 人类晨会（30 分钟）：你只看三样：日报、卡住清单、决策请求。批方向、拆障碍、把"卡住"任务重新指路。
09:30 之后：你去上班，AI 继续。周期往复。每周日你把通过验收的里程碑打 tag，不可逆存档。
不是"全自动"，而是"高杠杆的半自动"。宣称完全不需要人的方案，通常把成本转嫁成了你不敢看的技术债。

在 7×24 自主开发循环里，人每天最值得花时间做的三件事是？

本章小结：把人定位成监理而非施工员。人管方向、验收、卡点；AI 管执行的全部体力活。

长程任务的解剖学

一个能被 AI 长期执行的任务 = 明确的终局（里程碑）× 可判定的验收 × 可回退的检查点。

把"复刻 Photoshop"这句话拆开，它其实是几百个任务的集合。管理它们的经典框架叫 WBS（Work Breakdown Structure，工作分解结构）：像切蛋糕一样，把大工程切成"小到一次会话能做完、做完能单独验证"的任务。

三件套

构件是什么Photoshop 复刻中的例子
里程碑对外可见的阶段性成果，粗粒度、不可跳M3：能打开 PNG、画笔涂鸦、保存
验收标准（DoD）每个任务"做完"的可执行判定，最好是脚本pytest tests/test_brush.py 全绿 + 截图 diff 误差 < 1%
检查点随时可回退的存档每个任务一个 Git commit；每个里程碑一个 tag
没有验收标准的任务清单，就像没有尺寸和交货日期的装修合同——施工队可以永远"在推进"，你永远无法说"这不对"。

为什么验收标准必须可执行？因为执行者是 AI：它对"界面要好看"这种描述会自由发挥，但对"这 12 个测试必须全绿"没有辩解空间。给 AI 的每条验收标准都应当是一条命令。

把大工程切成"一次会话能做完、做完能单独验证"的小任务，这个过程叫任务 ；每个任务完成的可执行判定叫验收标准，也常写作 DoD（Definition of 的缩写）。

本章小结：里程碑定方向，验收标准定对错，检查点定退路。三者都写进仓库文件，AI 和人共用同一份事实。

流水线上的五种 Agent

不要用一个"全能 AI"扛下所有角色——用一组分工明确的 Agent 组成流水线，每个角色有专属的输入、输出和工具。

单 Agent 的问题：上下文塞满了调研资料时，写代码质量下降；写代码写嗨了，就忘了调研结论。解法借鉴人类软件团队：按角色分工，用文档交接。

角色职责交接物（给下一站）
🔎 研究员搜索、筛选、整理外部资料与代码库现状docs/research/*.md（带出处的摘要）
📐 架构师把需求变成模块设计与接口约定docs/design/*.md（接口签名 + 数据流）
📋 计划员（PM）把设计拆成任务队列，标注依赖与验收docs/tasks/queue.md（任务卡）
⌨️ 工程师领任务卡写代码，自测通过后提交Git commit + 测试报告
🧪 验证员独立于工程师跑全量测试与验收脚本docs/reports/*.md（通过/失败/风险）
交接物全是仓库里的文件，不是聊天记录。这保证了：任何 Agent 重启后可以只读文件恢复状态；任何人都能审计 AI 的推理链。

注意一个关键设计：验证员不能是写代码的那个 Agent。自己批改自己的作业，错误会一路绿灯。即使底层是同一个模型，也要用独立会话、只给它验收脚本而不是实现过程。

把 Photoshop 复刻的一条流水线排成正确顺序
工程师领取任务卡，实现图层数据结构
研究员整理"图层合成算法"的资料并写入 docs/research/
验证员独立运行验收脚本，出具通过/失败报告
架构师基于资料设计 Layer/Canvas 接口
计划员把设计拆成带验收标准的任务卡入队

为什么验证 Agent 要与写代码的 Agent 分离（独立会话）？

本章小结：多 Agent 不是为了"热闹"，而是为了关注点分离。角色之间只通过仓库文件交接，验证与实现必须分家。

上下文工程：让 AI 记得住

AI 每次会话都"失忆"。对抗失忆的武器不是更长的上下文窗口，而是把关键知识沉淀到仓库文件里，让"读文件"代替"回忆"。

先认识本课的核心矛盾。模型的上下文窗口（一次能读进去的文本上限）在变大，但大不等于够用，而且有两条铁律：

  • 会话会结束：进程崩溃、超时、换模型，一切"聊过的内容"归零；
  • 上下文会稀释：窗口塞得越满，模型对其中单条信息的遵循度越低（业界常说的"上下文腐化"现象）。

三层记忆

层载体内容生命周期
工作记忆当前会话窗口正在做的任务细节一次会话
项目记忆AGENTS.md / CLAUDE.md、docs/约定、架构、进度、决策日志长期（随仓库演进）
原始记忆Git 历史、测试报告归档完整可追溯的证据链永久

每个 Agent 回合的第一步都是"读项目记忆"，最后一步都是"把新知识写回项目记忆"。这样即使换模型、换工具、隔一个月再继续，都能冷启动。

项目记忆就像工地墙上的施工日志。老师傅走了，新师傅来了，只要日志在，工程就能接着干。把日志记在脑子里（会话里）的团队，换人即归零。

但不是什么都往里写。下面的演示展示了一个残酷事实：每次"压缩"旧上下文，没被锚定的知识都会损失，且损失是复利式的。

拖动滑块：知识如何在多轮会话中存活（或死亡）

公式一目了然。经过 $c$ 次压缩后，有效知识留存率 $K$ 为：

$$K_c = a + (1-a)\,r^{\,c}$$

其中 $a$ 是写进文档（锚定）的知识占比，$r$ 是每次压缩对"只存在于会话里的知识"的保留率。因为 $r^c$ 是指数衰减，只靠"窗口够大"是慢性死亡，写文档才是复利。

按上面的公式，a=0、r=0.6 时，经过 5 次压缩后游离知识还剩多少？

本章小结：把知识写进仓库（AGENTS.md、docs/、决策日志），每次会话先读后写。上下文窗口是 RAM，仓库文件才是硬盘。

自主循环：计划 → 执行 → 验证 → 复盘

长程自主的引擎是一个简单循环：领任务 → 做任务 → 验收 → 写回状态。循环每转一圈，项目就确定地前进一格。

把前两章的零件拼成机器。一个"任务回合"（agent turn）的标准流程：

任务回合的六个动作
① 读状态：读 AGENTS.md + 任务队列 + 上一回合日报，恢复上下文（对应上一章的冷启动）。
② 领任务：按优先级取第一张"未开始"且依赖已满足的任务卡，标记为"进行中"（防止多个并行 Agent 撞车，用文件锁或状态字段）。
③ 执行：必要时先派调研，再写代码；遵循仓库内的代码约定。
④ 自验：跑该任务的验收命令；失败最多重试 3 次，把每次失败原因记入任务卡。
⑤ 写回：更新任务状态、写 commit、把新学到的知识沉淀到 docs/。卡住则附上"卡点报告 + 我的尝试"。
⑥ 复盘钩子：每 N 回合触发一次自检——"最近的任务是不是都卡在同一处？验收标准是不是太模糊？要不要升级给人类？"

这个循环里最重要的工程性质是：任何一步崩溃，下一回合都能从文件状态无损恢复。这叫幂等的循环——重启不是灾难，只是又一次普通的开工。

接下来是本课的核心演示：调整流水线参数，观察"复刻 Photoshop"的工期如何变化。

自主开发流水线模拟器：60 个任务 × 四阶段 × N 个 Agent

每个任务依次经过：研究(2h) → 编码(4h) → 测试(2h) → 验证(1h)。失败的任务退回研究重做；设了审查间隔时，验证过的任务要等到审查窗口才正式计入完成。

试着玩出这几个现象（可用模拟器自己复现验证）：

  • 固定 Agent 数（比如 3），把失败率从 0 调到 0.5：工期从约 8 天涨到约 15 天——任务一个没多，多出来的时间全是返工吃的；
  • 把 Agent 从 1 拉到 8（失败率固定 0.3）：天数等比变短，但返工件数几乎不变——加人只能压缩时间，治不了质量，返工照旧按件数吞掉近半工时；
  • 把审查间隔设为 0：完成得最快，但那是无人验收的完成——数量快了，质量没人兜底（此时模拟器里的"完成"并不可信）；
  • 合理的甜点区：低失败率 + 中等并发 + 保留审查卡点。

模拟器里（Agent=3），把失败率从 0.1 提到 0.4，工期明显变长、返工次数从个位数涨到几十次。最根本的机制是？

本章小结：自主循环的可靠性来自文件化状态 + 幂等重启 + 重试上限；工期的敌人不是 AI 写得慢，而是返工。

质量闸门：让 AI 自己发现"没做对"

AI 报告"已完成"不等于真完成。质量闸门 = 一组合起来跑一遍就知道真假的自动检查，粒度越细，整体成功率越高。

AI 编码有个稳定的坏习惯：幻觉完成——测试里偷偷 try/except 吞掉异常、把断言改弱、"暂时跳过"后忘了恢复。对策不是盯得更紧，而是建立三层闸门：

闸门检查什么例子（Photoshop 复刻）
🚪 快速门单测 + lint + 类型检查，每个任务必过卷积核数学正确性、命令类接口契约
🖼️ 像素门金样本回归：与基准输出逐像素比对对标准测试图应用滤镜，与参考输出 diff
👤 体验门人抽测关键路径，或用截图+多模态模型粗查 UI打开→画笔→撤销→保存 一条龙

为什么强调细粒度任务？一个数学事实：假设每个任务独立地以概率 $p$ 一次做对，$N$ 个任务全部一次通过的概率是

$$P = p^{N}$$

指数衰减意味着：哪怕单任务成功率高达 95%，100 个任务全部不返工的概率也只有 $0.95^{100} \approx 0.6\%$。下面亲眼看这条曲线多陡：

任务粒度的残酷数学：P = p^N

结论反直觉但重要：把任务切小（同一个工程切成更多、更小、更好验证的任务）不仅不是拖延，反而是提高整体成功率的杠杆——因为小任务的 $p$ 更高，而且失败了返工损失更小（回到上一章的返工黑洞）。

常见误区：靠"让 AI 写更少的测试"来提速。测试正是 $p$ 的来源——砍测试等于把 $p$ 从 0.95 砍到 0.7，然后在 $0.7^{100}$ 里体会绝望。

p=0.9、N=100 时 P≈0.003。下面哪个做法最能改善局面？

本章小结：质量闸门三层——快速门、金样本门、体验门；任务切小是提升长程成功率的第一杠杆，$P=p^N$ 是它的数学底牌。

失败模式手册

每一个失败模式都有名字、有症状、有解药。开跑之前把这份手册贴在墙上，比任何模型选型都值钱。

以下是长程 AI 项目最高频的六种死法。先自己猜一猜解药，再翻卡核对。

六种失败模式（正面是症状，翻面是解药）
幻觉完成
解药：验收必须是独立可执行脚本；验证员与实现者分离；禁止修改测试文件（CI 里测试文件只读）。
上下文漂移
解药：短会话 + 冷启动读文件；每个会话只装一个任务的上下文；里程碑级共识写进 AGENTS.md。
代码腐化
解药：设"重构任务"进队列定期跑；lint/复杂度指标做硬闸门；架构师 Agent 定期审计代码一致性。
死循环烧钱
解药：重试上限（3 次）+ 单任务预算上限 + 连续失败 N 次自动升级给人类。
目标漂移
解药：里程碑不可随意改；变更走"决策日志"留痕；每周人类校准方向。
依赖地狱
解药：锁文件 + 环境快照进容器；引入新依赖需过"架构师"审查并记入决策日志。

这些失败模式有个共同根源：反馈回路太长。错误越晚被发现，修正成本越高——所以整套方法论的核心动作都是"把反馈提前"：小任务、快验收、每日审查、独立验证。

AI 连续 5 次修同一个 bug 越修越糟，还在继续尝试。最优先应该？

本章小结：给每个失败模式起名字，配"症状 → 解药"卡片。所有解药指向同一条原则：缩短反馈回路，永远给循环装保险丝。

实战推演：复刻 Photoshop 的路线图

把前面所有零件装进一个真实的里程碑计划：从"能画一笔"到"图层与滤镜"，每个阶段都有可执行的验收。

先划清范围：这里说的是教学复刻版——单机、开源技术栈（如 TypeScript + Web Canvas 或 C++ + Qt）、目标是覆盖 PS 核心概念（文档/画布、选区、图层、绘图、变换、滤镜、历史记录），而不是商业版的全部功能。

从 M0 到 M6：一个可被 AI 执行的里程碑序列
M0 · 空壳与地基（1 周）：窗口 + 画布渲染 + 十字光标。验收：应用能启动，画布显示 100% 灰色测试图。
M1 · 像素与文档（2 周）：图像数据结构（Uint8ClampedArray 缓冲）、打开/保存 PNG。验收：pytest round-trip 像素完全一致。
M2 · 工具与撤销（3 周）：铅笔/橡皮 + 命令模式 + 历史记录栈。验收：任意 50 步操作序列，undo/redo 后像素与金样本一致。
M3 · 选区与变换（4 周）：矩形/套索选区、裁剪、缩放旋转（双线性插值）。验收：选区外像素保护测试 + 变换数学单测。
M4 · 图层系统（5 周）：图层栈、不透明度、混合模式（先做 Normal/Multiply/Screen/Overlay）。验收：与参考实现（如已有开源库输出）逐像素 diff。
M5 · 调整与滤镜（4 周）：亮度对比度、曲线、高斯模糊（可分离卷积）、锐化。验收：PSD/公开测试图上的金样本回归全绿。
M6 · 打磨与插件化（持续）：性能（脏矩形重绘）、快捷键、滤镜插件接口。验收：10k×10k 图层模糊 < 2s 等性能指标。
注意每个里程碑的验收都是可执行命令（第 3 章的三件套）。这套路线图本身就是给 AI 的"宪法"：任何 Agent 任何时刻读一遍就知道身在何处、下一步做什么。
想一想：如果 AI 自作主张跳过 M2 直接做 M4（图层），会出什么事？

图层操作几乎必然产生"需要撤销"的错误状态，没有命令模式与历史栈，验证员无法用脚本断言"操作序列 → 预期像素"，只能靠人眼看——验收体系直接塌方；而且后续每个里程碑都会隐式依赖这个缺失的地基，返工成本随时间复利增长。解药：任务卡上写明依赖关系（M4 depends on M2），计划员 Agent 负责强制拓扑顺序。

思考题：如果 AI 在日报里连续三天说"明天就能完成 M4"，你怎么设计机制避免这种乐观偏差？

答案方向：① 完成的定义不许口头化——M4 的验收是脚本，跑不过就不许在日报里勾"完成"；② 任务卡粒度化，日报统计"已验收任务数"而非"感觉进度"；③ 让计划员 Agent 基于历史吞吐（近 N 天实际完成任务数）做预测，而不是让执行者自己估；④ 人类在晨会抽查 1–2 个"已完成"任务，让虚报有被抓的成本。

最终心法：你不是在"用 AI 写代码"，而是在设计一台 AI 能长期稳定运转的工厂。工厂的图纸——里程碑、验收、记忆、闸门、保险丝——都写在仓库里，人只做机器做不了的事：定方向、立标准、裁决例外。
