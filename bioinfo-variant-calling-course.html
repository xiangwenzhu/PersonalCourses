基因组变异检测实战：从 BAM 到 VCF

什么是变异检测

变异检测（Variant Calling）就是从测序 reads 中找出"你的基因组和参考基因组不一样的地方"，核心两类是 SNP 和 Indel。

每个人的基因组约 30 亿个碱基，与参考基因组（如 GRCh38）相比有大约 500 万个差异位点。变异检测的任务就是把这些位点逐个找出来，并判断基因型（纯合/杂合）。

两大类变异

  • SNP（单核苷酸多态性）：单个碱基变了，如 A → G。占绝大多数，是 GWAS 的主要研究对象。
  • Indel（插入缺失）：少了一个或几个碱基，或多了几个碱基。比 SNP 难检测，因为会影响比对。

生殖系 vs 体细胞突变

生殖系变异（germline）体细胞突变（somatic）
存在于全身所有细胞，可遗传仅肿瘤细胞，后天获得
样本血液/口腔拭子（单个样本）肿瘤-正常配对样本
典型工具GATK HaplotypeCaller、DeepVariantMutect2、Strelka2
预期频率0%、50%（杂合）、100%任意低频率（如 5% 亚克隆）
参考基因组像"标准答案"，你的 reads 是"考生的答卷"。变异检测就是批改答卷：哪里写错了（SNP），哪里多写/漏写了几个字（Indel）。杂合变异像答卷上涂改了一半的字——一半的 reads 说 A，一半的 reads 说 G。
点击卡片，分清 4 个易混概念
SNP vs 突变
SNP 强调"群体中常见的序列差异"（频率 ≥1%）；突变（mutation）强调"致病或罕见改变"。同一改变可以是 SNP 也可以是突变，取决于频率和后果。
杂合（Heterozygous）
两条染色体上碱基不同（如 A/G），变异 reads 约占 50%。VCF 中记为 0/1。
纯合（Homozygous）
两条染色体碱基相同。可以是纯合参考（0/0）或纯合变异（1/1，~100% reads 支持）。
VAF（变异等位基因频率）
支持变异的 reads 数 / 总覆盖 reads 数。生殖系杂合约 50%，体细胞突变可为任意值，是判断克隆比例的关键。
变异检测的本质是统计问题：在某位点观察到 k 条 reads 支持变异、n 条总覆盖，判断"这是真变异还是测序/比对错误"。

一个位点总覆盖 30 条 reads，其中 28 条支持 G（参考是 A），2 条支持 A。最可能的基因型是什么？

SNP、Indel、生殖系、体细胞——这四个词是变异检测的基本词汇。接下来看它们怎么从 BAM 文件里被"call"出来。

变异检测流程概览

标准流程：BAM → 预处理 → calling → VCF。两大主流工具是 GATK（规则+统计模型）和 DeepVariant（深度学习）。

动手排一排：变异检测的正确顺序
变异 calling（HaplotypeCaller）
比对生成 BAM（BWA-mem2）
过滤与质控（VQSR / hard filter）
BAM 预处理（标记重复 + BQSR）
合并样本 & 基因型判定（GenotypeGVCFs）

GATK vs DeepVariant

GATK（Best Practices）DeepVariant
原理局部单倍型组装 + 贝叶斯基因型似然把比对区域编码成"图像"，用 CNN 识别变异
优势行业标准、文档生态全、VQSR 成熟精确度更高（尤其 Indel）、无需 BQSR
劣势步骤繁琐、参数多计算量大、可解释性差

输出：VCF 文件

#CHROM  POS     ID  REF  ALT   QUAL  FILTER  INFO          FORMAT  SAMPLE
chr1    123456  .   A    G     542   PASS    DP=32;AF=0.47  GT:AD:DP:GQ  0/1:17,15:32:99
chr1    234567  .   C    CT    128   q10     DP=8;AF=0.5    GT:AD:DP:GQ  0/1:4,4:8:45

关键字段：GT（基因型，0/1=杂合）、AD（参考/变异 reads 数）、DP（总深度）、GQ（基因型质量，错误率的 -10log10）、FILTER（是否通过质控）。

VCF 就是变异检测的"成绩单"：每行是一个位点（考点），REF/ALT 是标准答案和你的答案，QUAL 是阅卷置信度，FILTER=PASS 才算及格。
WGS（全基因组）覆盖均一但数据量大；WES（全外显子）只测 1-2% 基因组、深度高（100x+），适合找编码区致病变异。

VCF 中某位点 GT=0/1、AD=20,18、DP=38，说明什么？

流程是骨架：比对 → 预处理 → calling → VCF。工具可以换，但思路不变。下面深入每一步的机制。

比对结果预处理：让 BAM 更干净

Calling 之前必须做三件事：标记 PCR 重复、碱基质量校正（BQSR）、Indel 局部重比对。目的是去掉系统性误差，否则 caller 会把假信号当真变异。

① 标记重复（MarkDuplicates）

PCR 扩增会让同一片段被复制多份，这些"双胞胎 reads"并不提供独立证据。标记重复后，caller 只把重复 reads 算作一次观测，避免虚假的高深度支持假变异。

② BQSR（Base Quality Score Recalibration）

测序仪报告的碱基质量（Q 值）往往有系统性偏差：某些循环位置、某些碱基组合的质量被高估或低估。BQSR 用已知的 dbSNP 变异位点做"训练集"，建立 观测错误率 → 真实错误率 的校正模型：

$$ Q_{\text{recal}} = Q_{\text{reported}} + f(\text{read group}, \text{cycle}, \text{context}) $$

③ Indel 局部重比对（LeftAlignIndels / IndelRealigner）

同一个 Indel 可能被比对到多个等价位置（比对模糊性），导致同一变异在不同 reads 中"看起来不一样"。局部重比对把附近 reads 重新组装，统一 Indel 位置。

预处理像"考试前的考场整顿"：标记重复是把抄袭答案只算一份（防止一个人投 30 张雷同答卷干扰判卷），BQSR 是校准阅卷老师的评分尺度（有的老师手松手紧），重比对是把写在格线外的答案誊回格子里。
跳过标记重复会怎样？一个 PCR 错误被复制 20 份，caller 看到"20/40 支持变异"会误判为真实杂合变异。实际独立证据只有 1 条！
GATK 预处理命令流（点击展开）
① 排序 + 标记重复
gatk MarkDuplicates -I sorted.bam -O dedup.bam -M metrics.txt
② 建立比对索引
samtools index dedup.bam
③ BQSR（分析 + 应用）
gatk BaseRecalibrator -I dedup.bam --known-sites dbsnp.vcf -O recal.table
gatk ApplyBQSR -I dedup.bam --bqsr-recal-file recal.table -O recal.bam
④ 得到干净的 recal.bam，进入 calling

为什么标记重复对变异检测很重要？

预处理不"产生"变异，只"净化"证据。垃圾进垃圾出——预处理马虎，后面所有结果都是沙滩上的城堡。

变异 Calling 原理：HaplotypeCaller 如何思考

HaplotypeCaller 不逐位点独立判断，而是把活跃区域重新组装成单倍型（haplotype），再通过 PairHMM 计算每条 reads 来自各单倍型的概率，最后用贝叶斯公式算基因型似然。

三步拆解

HaplotypeCaller 内部机制
① 识别活跃区域：某区域有 reads 与参考不一致，标记为"活跃"，进入局部组装。
② 局部单倍型组装：用 de Bruijn 图把该区域 reads 组装成几条候选单倍型（如 参考型、SNP 型、Indel 型）。
③ PairHMM 比对：把每条 read 与每条候选单倍型做带质量值的比对，得到似然 $P(\text{read} \mid \text{haplotype})$。
④ 基因型似然与判定：对三种基因型（0/0、0/1、1/1）汇总似然，取最大者，并用 GQ 表示置信度。

基因型似然的贝叶斯框架

对基因型 $G$（如 0/1），其似然为所有 reads 似然的乘积：

$$ P(D \mid G) = \prod_{i} P(r_i \mid G) \approx \prod_{i} \frac{P(r_i \mid H_1) + P(r_i \mid H_2)}{2} $$

其中 $H_1, H_2$ 是基因型对应的两条单倍型。最终用贝叶斯后验比较各基因型，并输出质量值 $GQ = -10\log_{10} P(\text{错误基因型})$。

逐位点 caller 像"只看一个字母判对错"，HaplotypeCaller 像"把整段句子重新读一遍再判断"。Indel 之所以难，是因为缺失会让后面的 reads"整体移位"，只有联系上下文（单倍型组装）才能对齐。
HaplotypeCaller 的革命性在于：先组装、后判断。这把 Indel 检测从"比对的噩梦"变成"组装的问题"，大幅提升 Indel 精确度。
变异 Calling 演示：点击"运行 caller"，看 HaplotypeCaller 如何识别 SNP 和 Indel

为什么 HaplotypeCaller 对 Indel 的检测比传统逐位点方法更准？

"先组装后判断"是 HaplotypeCaller 的核心思想。理解了这个，就理解了为什么它对 Indel 更鲁棒、为什么深度和碱基质量都进入似然计算。

VCF 过滤与质控：去伪存真

Calling 输出的原始 VCF 含大量假阳性。两条过滤路线：VQSR（用机器学习按特征打分，适合大样本）和 hard filtering（设固定阈值，适合小样本/低深度）。

常用过滤维度

指标含义典型问题信号
QUAL位点存在变异的后验质量QUAL < 30 → 可能是假位点
QDQUAL / 深度QD < 2 → 高深度低质量，疑似重复区
MQ比对质量均值MQ < 40 → 比对不可靠（重复/低复杂度）
GQ基因型置信度GQ < 20 → 基因型判断错误率 > 1%
DP总深度过低（<10）→ 证据不足；过高 → 重复区
FS / SOR链偏倚变异只出现在一条链 → 疑似测序假象

VQSR vs Hard Filtering

Hard filtering 像"一刀切分数线"（QUAL≥30 且 QD≥2 且 MQ≥40）；VQSR 像"综合考评"：用大量高可信变异（HapMap、OMNI）做训练集，用 Gaussian 混合模型学出"真变异在特征空间长什么样"，给每个变异打 VQSLOD 分。
VQSR 需要足够数量的变异做训练（通常建议 ≥30 个样本联合 calling）。小样本强行跑 VQSR 会因训练集不足而失败或产生误导性结果，此时应退回到 hard filtering。

低深度的麻烦

深度是变异检测的命根子。杂合位点只有约一半的 reads 携带变异，所以在深度 $D$ 下，恰好观察到 0 条变异 reads 的概率是 $0.5^D$：

$$ P(\text{漏检杂合位点}) = 0.5^D $$

5x 时漏检率约 3%，10x 时约 0.1%，30x 时约十亿分之一。但低深度不仅漏检，还会把基因型判错（把纯合参考误判为杂合的"假阳性"也很多）。

测序深度模拟器：拖动滑块看杂合位点的检测可靠性

"看不到变异 reads" ≠ "没有变异"。在低深度下，杂合位点很容易被漏掉——阴性结果的可信度取决于深度。
过滤阈值演示：拖动 QUAL / GQ 阈值滑块，看多少变异被保留或过滤

VQSR 相比 hard filtering 的主要优势是什么？

过滤是精确度与召回率的权衡：阈值严 → 假阳性少但真变异被误杀；阈值松 → 反之。理解每个指标在量什么，才能设出合理的阈值。

联合 Calling 与大队列分析

GVCF 模式（HaplotypeCaller -ERC GVCF → GenotypeGVCFs）先对每个样本输出非参考块（NON_REF），再联合判定，保证大队列中"没 call 到变异"和"没有覆盖"不被混为一谈。

为什么需要联合 Calling

单个样本 calling 后合并 VCF 有两个问题：① 某样本在某位点没有变异记录，到底是"纯合参考"还是"没测到"？② 不同样本用不同参考置信度，合并时无法统一。GVCF 模式为每个样本记录所有位点（包括纯合参考）的基因型似然，合并时重新联合判定。

# ① 每个样本单独跑（-ERC GVCF）
gatk HaplotypeCaller -I sample1.recal.bam -O sample1.g.vcf -ERC GVCF
# ② 合并所有 gVCF
gatk GenomicsDBImport -V sample1.g.vcf -V sample2.g.vcf ... --genomicsdb-workspace-path db
# ③ 联合基因型判定
gatk GenotypeGVCFs -R ref.fa -V gendb://db -O cohort.vcf

队列级质控指标

指标健康范围（WGS）异常提示
Ti/Tv（转换/颠换比）~2.0-2.1明显偏低 → 假阳性多
het/hom 比~1.5-2.0过高 → 杂合假阳性；过低 → 近亲/污染
单样本变异数~4-5M（WGS）离群样本 → 质量问题或污染
SNP 一致性（重复样本）>99%低于此 → 样本搞混或污染
联合 calling 像"全班统一阅卷"：每个学生的答卷先扫描存档（gVCF，含所有题目的作答置信度），最后统一批卷（GenotypeGVCFs）。这样"某题空白"能被区分是"没答"还是"答案与标准一致所以没记录"。
Ti/Tv 是变异检测的"体温计"：人类基因组真实变异的 Ti/Tv ≈ 2.1，纯随机错误的 Ti/Tv ≈ 0.5。结果偏离 2.0 太多，说明 VCF 里混入了大量假阳性。

变异注释与致病性评估

Calling 找到变异只是开始。注释工具（VEP/ANNOVAR）叠加基因、转录本、频率、功能预测等数据库信息，再用 ACMG 指南综合判读致病性。

注释工具：VEP vs ANNOVAR

VEP（Ensembl）ANNOVAR
输出变异后果（consequence）分级基因型/区域/过滤三种注释
数据库Ensembl/GENCODE 转录本RefGene、dbNSFP 等广泛整合
特点标准、更新快、插件生态强灵活、支持自定义数据库

功能与致病性预测

  • SIFT：基于序列保守性，预测错义突变是否有害（D=有害，T=耐受）。
  • PolyPhen-2：基于结构域和序列特征预测错义突变影响（D=可能有害，P=可能，B=良性）。
  • CADD：整合多维度证据的综合性评分，CADD ≥ 20 表示位于全基因组有害变异前 1%。
  • ClinVar：变异-疾病关联数据库，标记 Pathogenic / Likely pathogenic / VUS / Benign。
  • gnomAD：大规模人群频率数据库，频率高 → 大概率良性（纯合致死变异不可能在人群中有 1% 频率）。

ACMG 指南：五条"非常强"证据

注释像"查档案"：变异是嫌疑人，VEP 查出他住哪个基因（住址）、改没改蛋白质（作案手法），ClinVar 查他有没有前科，gnomAD 查他在人群中的口碑。ACMG 像法官，按证据清单（28 条规则）综合量刑：Pathogenic / Likely pathogenic / VUS / Likely benign / Benign。
