生信人的 Linux 命令行实战

为什么生信离不开命令行

生信工具 90% 都没有图形界面；命令行不是"程序员的倔强"，而是处理百万级文件时唯一高效的方式。

一个 RNA-seq 项目动辄产生几十个 FASTQ 文件、几百 GB 数据。用鼠标点？不现实。用命令行，一行 for 循环就能把 100 个样本全部跑完，还能写成脚本永久复用。

图形界面像自动挡小轿车——市区代步舒服；命令行像手动挡重卡——载重 50 吨翻山越岭。生物数据就是那个"50 吨"。

管道与重定向：命令的乐高

| 把命令首尾相接，> 把结果写进文件——掌握这两个符号，你就有了无限组合的能力。

核心思想：每个命令只做一件事，管道负责组合。

示例拆解：从 100 万行日志中找出失败任务
cat pipeline.log —— 输出全部内容
grep "ERROR" —— 只留含 ERROR 的行
awk '{print $5}' —— 只取第 5 列（样本名）
sort | uniq -c —— 排序并统计每个样本失败次数
串起来：cat pipeline.log | grep "ERROR" | awk '{print $5}' | sort | uniq -c
管道像接力赛：前一棒（命令）的输出交给下一棒。每棒只跑自己那一段，最后冲线的是组合结果。
> 是"写入文件"（覆盖），>> 是"追加"，2> 是重定向错误。cmd > out.txt 2>&1 把正常和错误输出都存下来——跑流程必用。
管道构建器：勾选步骤，实时看数据如何被一步步处理

command >> result.txt 中的 >> 是什么意思？

管道的威力在于"分解问题"：复杂任务拆成简单步骤，每步一个命令。这是 Unix 哲学，也是生信思维。

文本三剑客：grep、awk、sed

grep 找行、awk 取列并计算、sed 改内容——三剑合璧，可在不打开文件的情况下完成 90% 的文本处理。

各自分工

工具特长生信典型用法
grep按模式匹配行从 GFF 文件提取某基因的所有注释行
awk按列处理 + 算术算 BED 文件每条区间长度（$3-$2）
sed流式编辑替换把 FASTA 头行统一改名
# 例1：提取 1 号染色体上的基因
grep "^chr1" genes.gff

# 例2：算每个区间的长度并输出
awk '{print $1, $3-$2}' regions.bed

# 例3：把样本名从 old 批量改成 new
sed 's/old_sample/new_sample/g' file.txt
处理一个表格：grep 是"筛选行"，awk 是"选列 + 算数"，sed 是"查找替换"。Excel 能做的它们都能做，且快 1000 倍。
awk 默认按空白分列：$1 是第一列，$0 是整行，NR 是行号。记住这三个，就能完成大半工作。

实战：FASTQ 文件体检不求人

拿到一个陌生 FASTQ，用命令行 60 秒内摸清：多少条 reads、多长、质量行什么水平、有没有接头污染。

FASTQ 格式回顾

每 4 行 = 1 条 read：

@SEQ_ID          # 第1行：序列标识
GATTTGGGGTTCAA...  # 第2行：碱基序列
+               # 第3行：分隔符（可重复ID）
!''*((((***+))   # 第4行：质量值（ASCII 编码）

实战命令清单

一步步体检一个 FASTQ 文件
① 多少条 reads？
wc -l sample.fq → 行数 ÷ 4 = reads 数
② reads 多长？
head -n 2 sample.fq | tail -n 1 | wc -c → 第一条序列字符数
③ 质量行 ASCII 范围？
sed -n '4~4p' sample.fq | head -1000 | fold -w1 | sort -u → 出现哪些质量字符
④ 有没有接头污染？
grep -c "AGATCGGAAGAGC" sample.fq → 出现次数
⑤ 序列复杂度？
awk 'NR%4==2' sample.fq | sort -u | wc -l → 有多少种唯一序列
这套组合拳像体检：量身高体重（reads 数）、看血常规（质量分布）、查传染病（接头污染）。不打开文件，60 秒出报告。
一键体检：点按钮，模拟对整个 FASTQ 跑完整套命令

真实场景中这些步骤由 FastQC / fastp 自动完成。但理解底层命令能让你看懂报告、排查问题，而不是只会点"运行"。
