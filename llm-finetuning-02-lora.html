大模型微调 · 第 2 课：LoRA 原理与调参

为什么需要 LoRA：只改一点点

第 1 课算过账：全量微调要把模型的每个参数连同梯度和优化器状态都搬进显存，动辄几十上百 GB。LoRA 的想法朴素得惊人——既然原来的模型已经很好，我们只训练一小片"补丁"，不去动整本书。

回忆第 1 课的结论：7B 模型全量微调，仅静态显存（参数 + 梯度 + Adam 状态）就约 84 GB，一张 24 GB 的消费级显卡连门都进不了。但我们微调的目的通常不是"重新教模型说话"，而是"让它学会一点点新习惯"——换一种口吻、记一套格式、懂一个领域的行话。

既然是"一点点新习惯"，为什么要重写整本书？这就是 LoRA（Low-Rank Adaptation，低秩适配） 的出发点：冻结原模型的全部参数，只往关键位置插入并训练两个小矩阵。训练结束后，两个小矩阵加起来往往只占原模型参数的千分之几，却足够让模型学会你的任务。

出版社要修订一本 1000 页的畅销书。重印全书（全量微调）成本巨大，而且一不小心改错字还会把原本对的内容改坏。聪明的做法是：正文一字不动，随书附一小叠"修订便签"（LoRA），读者把便签贴到对应的页面上就得到了新版。想回退？撕掉便签即可，原书毫发无损。
LoRA 的三重好处：① 显存省——只训练千分之几的参数，梯度与优化器状态也只需为这千分之几准备；② 不动原模型——旧能力天然被保护，灾难性遗忘大幅减轻（回想第 1 课的"防遗忘锁"）；③ 可插拔——一个底座可以配多个"便签"，针对不同任务随时切换。
翻卡：建立第一直觉
LoRA 是什么？
一种参数高效微调方法：冻结原模型，只训练插入的小矩阵（"修订便签"），用它来改变模型行为。
为什么省显存？
梯度与优化器状态只需为"被训练的少量参数"准备。训练 0.1% 的参数，优化器账就变成原来的约 0.1%。
原模型会变吗？
不会。原参数全程冻结、数值不变。新能力全部来自小矩阵，因此遗忘旧能力的风险也小得多。
什么时候用它？
你想改变模型的行为/风格/格式，但又没有全量微调那么大的显存预算时——尤其是一块消费级显卡想微调大模型。

LoRA 最核心的省钱原理是什么？

一句话记住本章：全量微调是"重印全书"，LoRA 是"贴修订便签"。便签虽小，选对位置（后面讲 target_modules）就能起到大作用。

低秩直觉：变化也许很简单

LoRA 赌的是一件事：微调带来的权重变化，可能"远比你想象的简单"。一种叫"秩"（rank）的量，就是用来衡量"一张表格的变化到底需要多少独立信息"的。

先做个思想实验。你要给一张照片调色：把整体调亮、加一点暖色调。这张照片有 100 万个像素，但你的修改其实只由两三个参数决定（亮度、色温）。换句话说：修改很复杂（100 万像素），描述修改的方式却很简单（两三个旋钮）。

LoRA 的作者发现，大模型微调时也存在类似现象：权重矩阵的变化 $\Delta W$，虽然本身很大，却常常可以由"很少的几行几列"近似表示。这个"很少的几"就是秩（rank）——粗略地说，秩是"这张表里有多少行是真正独立的、谁也代替不了谁"的度量。

一个班级 50 个学生的身高和体重表，看起来是两列独立数据；但如果大家只是按"壮实程度"不同成比例地又高又重，那这 50 行其实只由 1 个隐藏因素决定——秩就是 1。秩越低，表格里"冗余"越多，用少量信息就能近似还原整张表。

下面的演示帮你建立手感：拖动"独立因素数"滑块，看一张由隐藏因素生成的表格如何被"低秩近似"重建。注意重建误差随秩增加而下降的速度——你会发现误差下降很快趋缓，这正是 LoRA 敢用小矩阵的底气。

低秩近似演示：秩越小，需要的"独立信息"越少

示意：用随机因素矩阵模拟"真实变化表"，再用截断到前 r 个因素的方式重建，展示近似误差如何随 r 变化。真实权重变化不会这么规则，但"误差快速趋缓"的定性规律一致（LoRA 论文与大量后续实验的观察）。

把"秩"翻译成微调语言：微调要教会模型的"新变化"，可能只需要很少几个独立方向。既然如此，与其更新整个大矩阵，不如只学习这几个方向——这就是下一章公式 $\Delta W = BA$ 的全部秘密。

"权重更新的秩很低"这句话，最贴近的直觉解释是？

本章你只需要带走一个直觉：大变化 ≠ 复杂描述。微调带来的权重变化可能"内在很简单"（低秩），这为"只训练小矩阵"提供了依据。记住这个词——秩，下一章它会变成公式里的 r。

LoRA 核心公式拆解

全部内容浓缩成一行公式：$W' = W + \Delta W$，而 $\Delta W = BA$。原矩阵 $W$ 冻结，只训练又矮又胖的 $B$ 与又瘦又高的 $A$，两个矩阵相乘就得到一个"高瘦"的变化量。

先看结论公式，再逐项拆解：

$$W' = W + \Delta W, \qquad \Delta W = B A, \qquad A \in \mathbb{R}^{r \times k},\ B \in \mathbb{R}^{d \times r}$$

推理（或继续训练）时，输出变成 $W'x = Wx + BAx$：前半段走原模型，后半段走补丁。训练时只有 $A$、$B$ 里的数在更新，$W$ 一个数都不动。

公式分步揭示：一步步看每一项是什么
第 1 步：$W$ 是什么？ 原模型某一层里已有的权重矩阵，比如把"注意力查询向量"投影到新的空间。它有 $d$ 行 $k$ 列，微调时它全程冻结。
第 2 步：$\Delta W$ 是什么？ 我们希望权重的"变化量"。LoRA 的关键假设（上一章的直觉）：$\Delta W$ 是低秩的，可以被两个小矩阵的乘积近似。
第 3 步：$A$ 和 $B$ 各是什么？ $A$ 形状是 $r \times k$（"矮行"），$B$ 形状是 $d \times r$（"高列"）。它们相乘 $B A$ 恰好得到 $d \times k$，和 $W$ 一样大——但参数量只有 $(d{+}k) \times r$。
第 4 步：$r$ 是什么？ 秩（rank），那个"独立方向的数量"，也是 LoRA 最重要的超参数。$r$ 越小，参数越少、越省显存，但表达能力上限也越低。
第 5 步：为什么参数量骤减？ 若 $d=k=4096$、$r=16$：原矩阵 1680 万参数，LoRA 只需 $4096 \times 16 \times 2 \approx 13$ 万——约为原来的 0.8%。这就是"只改一点点"的数学表达。
第 6 步：scaling $\alpha / r$。 实际使用时常写成 $\Delta W = \frac{\alpha}{r} B A$。$A$ 初始化时乘了一个缩放系数，让新增部分在训练初期不至于太猛、影响训练稳定性；$\alpha$ 是另一个可调旋钮，常见做法是令 $\alpha$ 等于 $r$（即缩放为 1）作为起点。
把公式读成一句话：一个"高"的变化 = 一个"高瘦"的矩阵 × 一个"矮"的矩阵。用极少的参数（$r$ 控制）拼出足够的变化，这就是 LoRA 的数学核心。注意 $B$ 通常初始化为 0（保证训练起点时 $\Delta W = 0$，模型从原能力出发），$A$ 用很小的随机值初始化——不同实现细节可能略有差异。

LoRA 中 $A \in \mathbb{R}^{r \times k}$、$B \in \mathbb{R}^{d \times r}$，当 $d=k=4096$、$r=8$ 时，可训练参数量约为多少？

为什么很多 LoRA 实现把 $B$ 初始化为 0、$A$ 用很小的随机值初始化？

公式总结：$W' = W + \frac{\alpha}{r}BA$。$W$ 冻结；$A$、$B$ 是仅有的可训练参数；$r$ 是表达能力和省显存之间的旋钮；$\alpha/r$ 是稳定训练的缩放。别背，理解形状（高瘦 × 矮 = 高）就够了。

LoRA 四大超参数

rank（r）控制补丁的"厚度"，alpha 控制补丁的"力度"，dropout 是防过拟合的"噪音"，target_modules 决定补丁"贴在哪"。前三个是数，最后一个是关键的选择题。

用翻卡过一遍四大超参数，再看常见取值经验。

翻卡：四大超参数
rank (r)
小矩阵的中间维度，决定补丁的表达能力。常见 8–64。r 越大参数越多、可能效果更好，但收益递减、显存也随之上涨。
alpha (α)
与 r 一起构成缩放 α/r，控制 LoRA 分支输出的整体力度。常见做法 α=r（缩放为 1）起步，效果不够再调。
dropout
在 LoRA 分支里随机丢弃一部分信号，防止小数据下过拟合。常用 0–0.1；数据少或任务窄时可以调大一点点试试。
target_modules
决定给哪些层贴补丁：注意力里的 q/k/v/o 投影、MLP 里的 gate/up/down 投影。选得准比选得多更重要。

target_modules：贴在哪比贴多少重要

Transformer 层的每个注意力块里有四个投影矩阵：查询（q）、键（k）、值（v）、输出（o）；MLP 块里通常还有 gate、up、down 三个矩阵。你可以只对其中一部分插入 LoRA：

  • 只贴 q、v（LoRA 论文验证过的经典最小配置）：参数最少，很多任务已够用，适合先跑通流程。
  • q、k、v、o 全贴：最常见的默认选择，效果与成本的平衡点。
  • 再加上 MLP（gate/up/down）：表达上限更高，常用于更难的任务或数据相对充足时，但参数量与训练成本也明显上升。
不要默认"贴越多越好"。每层都贴、还加上 MLP，参数量可能翻好几倍，而过拟合和训练不稳定的概率也随之上升。从 q+v 或 qkvo 起步，效果不够再逐步扩大覆盖面——这和调学习率"宁小勿大"是同一个哲学。
超参数作用常见起点
rank r补丁的表达能力（厚度）8 或 16；效果不够再加到 32、64
alpha缩放 α/r，控制力度令 α = r（缩放 1）
dropout防过拟合0.05 左右，或数据少时试 0.1
target_modules补丁贴在哪q、k、v、o 四个注意力投影

注：以上是社区与论文中反复出现的经验区间，不是保证最优的定律。不同任务、不同底座的最优值差异可以很大，请以你自己的验证集为准。

如果你的 LoRA 训练出现了过拟合（训练集表现越来越好、验证集变差），优先考虑调哪个超参数、怎么调？

第一次跑 LoRA，想以最小成本先验证流程跑通，target_modules 怎么选比较合理？

调参起手式：r=16、α=16、dropout=0.05、target=qkvo。这是"不会错得太离谱"的默认配方；遇到过拟合就加 dropout / 减 r，遇到欠拟合就加 r / 扩大 target。

rank–参数量–效果：核心演示

这是本课最重要的演示：拖一拖 rank、输入维度、目标模块，实时看"可训练参数量、相对全量微调的比例、显存估计、经验性效果提示"怎么联动。所有数字都是示意估算，帮你建立数量级直觉。

先明确估算口径。对一层 $d \times k$ 的矩阵贴上 LoRA，可训练参数 = $d \times r + r \times k$（即 $A$ 与 $B$ 之和）。显存估算沿用第 1 课的简化口径：每个被训练参数约占 12 字节（FP16 参数 + FP16 梯度 + 2×FP32 Adam 状态），不含激活值。底座无论 LoRA 还是全量微调都要加载，所以两者可比的部分是"训练状态的增量"。

示意：矩阵数量 32 大致对应"只贴 qkvo"（7B 级模型约 32 层 × 4 个投影 ≈ 128 个矩阵；112 是再加 MLP 的上限附近）。效果是相对示意，不是实测数据；真实任务请以你的验证集为准。

怎么读这个演示

  • 参数量随 r 线性增长：r 翻倍，A、B 参数翻倍。但相对全量微调始终是"零头"——这正是 LoRA 省显存的来源。
  • 效果的"经验曲线"：r 从 1 加到 16 左右时，绝大多数任务的效果提升明显；16→64 仍有收益但明显放缓；64 以上常常接近饱和，除非任务本身特别复杂。注意这是社区经验的方向性描述，不是承诺。
  • 显存的两部分：底座加载（无论怎么微调都要付）+ 训练状态增量（LoRA 把它压到很小）。下一章的 QLoRA 会把第一部分也砍下来。
把滑块玩一遍，记住三句话：r 是线性旋钮（参数 ∝ r）、效果收益递减（8→16 常常值得，64→128 常常不值）、显存大头永远是底座（LoRA 只省训练状态，QLoRA 才动底座）。

在这个演示里，把"矩阵维度 d"从 4096 拉到 8192（r 不变），可训练参数量大约怎么变？

数量级锚点：7B 模型、qkvo 全贴、r=16，LoRA 可训练参数通常在千万级，约占全量的 0.1%–1%。这就是"一张消费级显卡也能微调大模型"的数学基础（再叠加 4bit 加载底座，就是下一章的 QLoRA）。

merge、多 LoRA 与 QLoRA

训练好的 LoRA 有两条出路：merge（把便签内容誊写进书里，得到单文件模型）或多 LoRA 热插拔（一个底座挂多个便签，按需切换）。而 QLoRA 再进一步：用 4bit 加载底座，把显存账砍到消费级显卡能扛住的程度。

merge：什么时候把补丁写回去

训练完成后，你可以把 $\Delta W$ 直接加回 $W$，得到一个新的完整权重文件。这个过程叫merge（合并）。

  • 适合 merge：微调结果定型、准备上线部署。合并后就是普通模型，推理时不再多算 $BA$ 这一支，没有额外计算开销，部署最简单。
  • 不适合 merge：还想在多个任务间切换（见下），或想随时退回原模型。merge 是单向的，合并后再想拆回来就麻烦了。
便签贴久了想定型成正式出版物，就把修订内容誊写进正文（merge），读者拿到的就是一本完整的新书，不用再贴便签。但如果你同时要维护"儿童版""专业版""英文版"多个修订方向，誊写三遍就太低效了——这时不如保留一叠便签，按需取用。

多 LoRA 热插拔

LoRA 文件通常只有几十 MB 到几百 MB，远小于完整模型。因此可以让一个底座同时挂载多个 LoRA 适配器，按请求动态切换：这个请求用"客服口吻 LoRA"，下一个请求切到"代码风格 LoRA"。这在服务多租户、多风格场景非常划算——底座只加载一份，显存里多出来的只是几个小文件。

QLoRA：4bit 加载底座

LoRA 把"训练状态"的账压下来了，但底座模型本身还是要完整加载进显存：7B FP16 ≈ 14 GB，13B ≈ 26 GB。QLoRA（Quantized LoRA）的思路：底座用 4bit 量化加载（参数缩到约 1/4），训练时按需反量化，而 LoRA 分支保持在较高精度正常训练。两者结合：

  • NF4（4-bit NormalFloat）：一种专为已近似正态分布的神经网络权重设计的量化格式，信息损失更小。
  • 双重量化（Double Quantization）：连量化所用的缩放系数也再次量化，再抠出一点显存。
  • paged_adamw_8bit：把 Adam 优化器状态压到 8bit，并用分页机制缓解显存峰值（应对长序列时显存突然不够的问题）。

QLoRA 的一句话定位：4bit 加载底座 + LoRA 只训小矩阵，两招叠加让 7B–13B 级模型的微调在 24GB–48GB 显存内可行。它是"一张消费卡微调大模型"的现实答案，也是第 3 课实战的主角。
