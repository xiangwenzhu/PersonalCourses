大模型微调 · 第 4 课：训练机制与超参

一个训练步到底发生了什么

你已经在第 3 课跑通了 SFT。现在把镜头拉近到一个「训练步」：模型答一遍题 → 对答案算错多少 → 找出每个旋钮该往哪拧、拧多少 → 真正拧一下。四个动作循环上千万次，模型就学成了。

先对齐两个第 3 课用过的词：样本（一条「提问 + 标准回答」的例题）和 loss（损失，一个打分：模型这次答得有多离谱，越大越离谱）。微调做的事，本质上就是拿着样本反复训练，把 loss 一点点压低。

把训练想象成考完试逐题订正：①先作答——不看答案自己写一遍；②对答案——红笔批改，算出扣了多少分；③复盘——不是简单说"我错了"，而是想清楚"哪一步的思路导致扣分，以后遇到同类题该怎么调整"；④订正——把真正想明白的那一个习惯改掉一点。一题一题循环下去，成绩就上去了。模型的一个训练步，就是完整做一遍这四件事。

这四件事在深度学习里有正式名字，第 2 层会经常用到，先混个脸熟（点开看解释，现在记不住也没关系）：

前向传播（Forward）—— 第 ① 步「作答」把样本里的提问从输入层一路算到输出层，得到模型自己的「作答」。之所以叫「前向」，是因为数据是从网络的入口向出口单向流动的。
损失（Loss）—— 第 ② 步「扣分」把模型的作答和标准答案逐词对比，算出一个分数。分数越大表示错得越离谱。训练的目标就是让它的平均値越来越小。
反向传播（Backpropagation）—— 第 ③ 步「复盘」从 loss 出发，往回逐层推算：刚才的每一个内部「旋钮」（参数）对这次扣分各负多大责任。结果就是每个旋钮得到一个「该往哪个方向拧、拧多少合适」的建议。
参数更新（Update）—— 第 ④ 步「订正」按复盘建议，把所有旋钮同时微调一小步。微调一小步是故意的：步子太大容易改过头，把原来会的东西也改坏了。
一个训练步 = 前向（作答）→ 算 loss（扣分）→ 反向传播（复盘每个旋钮的责任）→ 更新（订正）。训练 = 把这个循环重复成千上万次，直到 loss 降到满意的水平。
分步走一遍：一个训练步的完整过程
第 1 步 · 取一批样本。从训练集里取一小撮例题（比如 4 条），这叫一个 batch（一批）。为什么取一批而不是一条？一批的平均表现更稳定，不容易被个别怪题带偏。
第 2 步 · 前向作答。把这 4 条提问喂给模型，它逐词生成自己的回答——这就是它此刻的真实水平。
第 3 步 · 算 loss。把 4 条回答分别和标准答案对比，算出每条错多少，取平均得到这一批的 loss。
第 4 步 · 反向传播复盘。从 loss 往回推算：模型内部几十亿个旋钮，每一个对这次的错「贡献」了多少，各自该往哪个方向拧。
第 5 步 · 更新旋钮。把所有旋钮按建议各挪一小步。挪完，模型就比一秒前好了一点点。
第 6 步 · 循环。取下一批样本，重复以上全部。几万步之后，loss 曲线缓缓下降，模型就「学会」了你的数据。
一个训练步就是一次「作答→扣分→复盘→订正」的完整循环。四个环节里最值得注意的是「复盘」：它能精确说出每个旋钮该往哪拧——这正是训练能自动进行的奥秘。

loss 曲线长什么样

训练时最重要的仪表盘就是 loss 曲线——把每一步的 loss 画成折线。它只有三种基本形态：健康下降、一直降不动（没学会）、训练集降测试集涨（学过头了）。会读这张图，排障就成功了一半。

为什么曲线比单个数字重要？因为一张曲线的「形状」比某一点的取值信息量大多了：它下降得快还是慢、是否平稳、两条曲线是否分道扬镳……每种形状都对应一种明确的「病情」。

  • 形态一：健康下降。训练集 loss 稳定下降并趋于平缓。这是最想要的样子。
  • 形态二：一直降不动。loss 从一开始就几乎不动。模型基本没从数据里学到东西。
  • 形态三：训练集一路降，测试集反而上升。模型把训练题背下来了，却不会做新题。这有个专门的名字叫过拟合（overfitting，学过头：只记住了例题，没学到规律）。「测试集」是留给模型「考它没见过的题」的一批数据，用来检验真本事。
曲线诊断：三张图，分别是什么「病情」？（先猜，再点）
loss 曲线像孩子的成绩单曲线：稳步上升是健康学习（图 A）；原地踏步是根本没学进去（图 B）；「课堂测验分越来越高、期末统考越来越差」则是背题不求甚解（图 C）。看出形状，就知道该换教材、换方法还是调整强度。
记住三形态：①稳定下降＝正常；②原地不动＝欠拟合（没学会，常见原因是学习率太小、数据或模板有问题）；③训练降、测试升＝过拟合（学过头，该早停、加数据或正则）。这三张图是后面所有排障的基础。

「训练集 loss 一路降、测试集 loss 一路升」是哪种现象？该怎么办？

学习率：步子多大，才走得稳

学习率（learning rate）控制每次「订正」时旋钮挪动的幅度。太大：围着正确答案来回震荡甚至跑飞；太小：慢得离谱还容易被卡在小沟里。SFT 的 LoRA 典型值是 1e-4 ~ 2e-4，全参微调约 1e-5 ~ 2e-5。

回到「考试订正」的类比：复盘告诉你「这题你的解题习惯有问题」，而学习率决定你「这次下决心改多少」。

  • 学习率太大：每次大改，改完发现过头了，下次又大幅改回来——成绩上蹿下跳，甚至越改越差。这在曲线上表现为 震荡，严重时 loss 直接飙上天（发散）。
  • 学习率太小：每次只改一丁点。方向也许对，但考试都结束了你还没改完。曲线上表现为下降缓慢，且容易困在一个「还凑合但不够好」的局部区域。

warmup：为什么开头要「先慢后快」

直接用一个很大的学习率从头训，往往会震荡。一个简单有效的办法是 warmup（预热）：前 3%~10% 的训练步里，让学习率从一个很小的值线性爬到目标值，然后再正常训练。直觉是：训练开始时模型内部状态还很混乱，梯度方向不可靠，这时小步走避免「一开跑就摔跤」；等走稳了再放开速度。

学习率调度器：后期为什么要「减速」

越接近目标，步子越应该小——否则容易在最佳点附近反复 overshoot（冲过头）。调度器（scheduler）就是「按训练进度自动调整学习率」的时间表，三种最常见的：

调度器形状（学习率随步数）直觉适用
constant（恒定）一条横线始终匀速改极少数情况；多数时候不如衰减
linear（线性衰减）斜向下的一条直线后期稳定地慢下来常见、稳妥的默认选择
cosine（余弦衰减）先慢降、后陡降、尾部平缓的「钟形曲线」后期花更多时间在细调上SFT 中最常用，效果通常略好于 linear

实践中的标准配方是 warmup + cosine/linear：开头先热身，然后一路减速到训练结束。

「loss 震荡 = 学习率太大」是必要不充分条件：学习率大只是最常见的原因，数据里的脏样本、模板错配也可能造成异常波动。降学习率前，先看几条原始样本。

loss 曲线在高位剧烈震荡、不下降，最可能是什么原因？

学习率是「第一超参」：震荡先降它，太慢先看它。记住 LoRA ≈ 1e-4~2e-4、全参 ≈ 1e-5~2e-5，配合 warmup + cosine，能避开大多数坑。

batch size 与梯度累积

有效 batch = 单卡 batch × 梯度累积步数 × 卡数。显卡装不下大 batch 时，梯度累积让你「多算几小步、再合并成一大步」——效果和一口气跑大批次几乎一样。

一次训练步处理多少条样本，由 batch size（批大小）决定。为什么不是一次只处理一条、或者一次全塞进显卡？因为：一批样本算出来的「平均梯度」比单条样本稳定得多——单条样本可能是怪题，把模型带偏；一批的平均就像「全班平均分」，方向更靠谱。但 batch 越大，显存占用也越大，显卡装不下就得想办法。

办法有两个：

  • 多卡并行：数据切到多张显卡上同时算，最后合并梯度。
  • 梯度累积（gradient accumulation）：显存只装得下 4 条？那就每次算 4 条、但先不更新参数，把梯度「攒着」；攒够比如 8 次，把这 8 小步的梯度加起来，一次性做一次大更新。效果约等于一次处理了 32 条。代价是同样的总步数里参数更新的次数变少了，训练显得「慢一些」。

三者相乘就是「模型每次更新参数时，实际看过多少条样本」，称为有效 batch size：

$$ \text{有效 batch} = \text{单卡 batch} \times \text{梯度累积步数} \times \text{GPU 数} $$
有效 batch 计算器：输入三个因子，实时计算

大 batch 要配大学习率

有一个来自实践的经验法则：有效 batch 越大，学习率也可以（且应该）适当调大。直觉很直白：大批次的梯度估计更准，迈步子可以更有底气；反过来，小批次配大学习率容易被个别样本带得震荡。所以你看到别人「batch 64 + lr 2e-4」效果好，直接照抄成「batch 8 + lr 2e-4」很可能翻车——有效 batch 差了 8 倍。这不是严格定律，不同任务敏感度不同，但当有效 batch 改动超过 4 倍时，值得相应调整学习率。

batch 像「一次批改多少张卷子」：改一张就下结论，容易被某张奇葩卷子误导；改一叠再总结规律，结论稳得多。而梯度累积就是「桌子小放不下整叠卷子，分批拿上来，但最后只写一次总结」。

单卡 batch=2、梯度累积=16、1 张 GPU，有效 batch 是多少？

有效 batch = per_device × accum × GPUs。OOM 先降 per_device 并用 accum 补回来，保持有效 batch 不变，学习率就不用重调。改动有效 batch 超过 4 倍时，记得联动调整学习率。

混合精度 bf16/fp16

训练时大多数运算改用 16 位浮点数（bf16 或 fp16），权重和梯度仍保留一份 32 位副本：显存几乎减半、矩阵计算更快，而精度损失在微调场景几乎无感。这正是现代训练默认开启的加速手段。

先解释「精度」。模型里的数值（权重、梯度）默认用 fp32（32 位浮点数）存储：小数点前后的有效数字多，表达精确。而 bf16 / fp16（16 位浮点数）只有它一半的位数：数字占的存储空间减半，显卡做矩阵乘法也快得多。代价是有效数字变少——就像把「3.14159265」记成「3.14」，粗略了，但很多时候够用了。

那为什么不全程用 16 位？因为有个麻烦：反向传播算出来的梯度往往非常小（比如 0.0001 这种量级）。16 位数的「表达能力」有限，太小的数可能被直接表示成 0——梯度一旦变 0，对应的旋钮就永远停住不学了。这个现象叫「下溢」。

bf16 与 fp16 的区别正好在这里：bf16 位数少但「指数范围」和 fp32 一样大，不容易下溢，所以基本不需要特殊处理；fp16 范围窄，更容易下溢，但部分老显卡（如 V100）不支持 bf16，只能用 fp16。

fp16 时代为此发明了 loss scaling（损失缩放）：训练前先把 loss 人为乘上一个很大的数（如 2^16），于是梯度也跟着放大，远离「小到被表示成 0」的危险区；更新参数前再除回去，数值恢复原样。对训练逻辑完全透明，只是给数「穿件大衣」再脱掉的技巧。用 bf16 时这一步基本可以省掉。

「混合精度」= 前向/反向用 16 位（快、省）＋ 关键数值保留 32 位副本（稳）。bf16 是首选：不需要 loss scaling，也不牺牲数值范围；硬件不支持时才退回 fp16 + loss scaling。

用 fp16 训练时 loss scaling（损失缩放）是为了解决什么问题？

混合精度 = 快与省的手段，不是「偷工减料」：bf16 因其指数范围与 fp32 相同而成为首选；fp16 需要 loss scaling 防下溢。两者都让显存近似减半——下一章你会看到这个省下来的空间可以用来换更长的序列。

梯度检查点：用时间换显存

反向传播需要前向传播的中间结果，默认全部存着——这是显存大头。梯度检查点（gradient checkpointing）只存一小部分「快照」，其余需要时重算：显存可省一大截，代价是训练慢约 20%~30%。OOM 时的标准手段。

把前向传播想象成解一道多步大题：每一步的中间结果（每一层的输出）默认都被写在草稿纸上，因为反向传播「复盘」时要逐层往回用。草稿纸越堆越多——层数多、序列长时，这些中间结果比模型权重本身还占地方。

梯度检查点的做法很「抠门」也很聪明：只在网络的少数几个位置保存快照（草稿纸只留关键页），反向传播需要某层的中间结果时，从最近的快照把那一段前向计算重算一遍。用重复计算（时间）换回了存储（显存）。

什么时候开？

  • 开了混合精度仍然 OOM → 开。
  • 想训更长的序列 / 更大的 batch（把省下的显存投资回去）→ 开。
  • 7B 及以上全参微调 → 基本都开。
  • 训练速度已经很吃紧、显存又够用 → 可以不开。

大多数框架里它是一个布尔开关，只决定「开不开」；少数实现允许你设置「每隔多少层存一个快照」——存得越频繁，显存省得越少、重算也越少。

显存-速度权衡台：开关两个特性，实时看影响（数值为教学示意）

模型权重 优化器状态（动量等） 梯度 中间结果
中间结果好比装修房子的过程照片。默认全留着（万一要用）；检查点就是只留开工、水电、木工等几个节点的照片，需要某个具体画面时按节点照片「补拍」一次。相册薄了，但要花点时间重拍。

开启梯度检查点的主要代价是什么？

显存四大件：权重、优化器状态、梯度、中间结果。bf16 砍前两种的大小，检查点砍第四种。组合拳（bf16 + 检查点）是 7B 全参微调能装进单卡的关键。

超参速查与训练诊断器

训练出问题不用慌：症状和旋钮之间是一张「表」。先看 loss 曲线的形状，对应到行，再按顺序调。这张表 + 下面的诊断器，覆盖微调 90% 的日常排障。

症状（loss 曲线 / 表现）最可能的原因该动哪个旋钮
震荡不下降、甚至飙高（发散）学习率过大学习率降一个数量级；确认 warmup 生效
下降缓慢或几乎不动（欠拟合）学习率过小 / 模板错配 / 数据有问题调大学习率；先抽 10 条样本人工检查；核对对话模板
训练集降、验证/测试集升（过拟合）学过头了提前停止；减少 epoch；加数据；增大 dropout
输出重复同一句话（复读机）学习率过大 或 epoch 过多（背题）降学习率、减 epoch；检查并去重训练数据
训完通用能力大损（遗忘）领域数据占比过高、缺少通用样本混入通用/复习数据，调低领域数据占比
训练直接 OOM（显存溢出）batch 过大 / 序列过长 / 未开省显存手段降 per_device_batch 并用梯度累积补；开 bf16 与梯度检查点；调小 cutoff_len
排障心法：一次只改一个旋钮，改完跑一小段看曲线再改下一个。同时动学习率、batch、数据三件事，出了问题你将无法归因。
训练诊断器：选症状，看处方

你的训练出现了哪种情况？

「症状→旋钮」表给的是「最可能的第一嫌疑」，不是定罪书。比如「loss 不动」的元凶经常是数据或模板问题而不是学习率——按表行动时，永远先花十分钟人工看几条原始样本。
进阶：几条不在表里的经验 ① 学习率调成原来的 1/10 或 10 倍都几乎无效时，问题多半不在学习率；② 「复读机」有时是因为数据里同一句话高频重复——先去重；③ 验证集 loss 开始回升的「拐点」就是最优点，之后的训练都是浪费甚至有害，做 checkpoint 选择时优先取拐点附近的存档；④ 复现别人的配置时，有效 batch 不同就要重新换算学习率。
把速查表收藏起来。遇到问题时：看曲线 → 对症状 → 一次只调一个旋钮 → 短跑验证。这套流程能搞定绝大多数训练异常。
