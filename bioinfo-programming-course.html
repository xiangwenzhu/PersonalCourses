Python/R 生信编程基础：Biopython 与 Bioconductor

为什么生信需要编程

命令行是"手工作坊"，编程是"自动化工厂"。当你要处理 100 个样本、重复 10 次分析时，编程是唯一可持续的方式。

前两课学了 Linux 命令和文件格式。但现实中的分析往往更复杂：

  • 对 50 个样本跑同一流程，每个样本参数略有不同
  • 从 GFF 文件提取特定类型的特征（如所有外显子长度 > 200bp）
  • 把 VCF 中的变异按基因分组，计算每个基因的突变频率
命令行像用计算器一个一个算，编程像写公式后批量填充。前者适合探索，后者适合生产。生信工程师必须两者都会。

Python 生信速通

掌握 Biopython 的 Seq 对象和文件解析，你就能处理 80% 的序列任务：读 FASTA、提取子序列、算 GC 含量、翻译蛋白质。

核心代码模式

# 读 FASTA 文件，计算每条序列的 GC 含量
from Bio import SeqIO

for record in SeqIO.parse("sequences.fasta", "fasta"):
    seq = record.seq
    gc = 100 * float(seq.count("G") + seq.count("C")) / len(seq)
    print(f"{record.id}: GC = {gc:.1f}%")

R 与 Bioconductor 入门

R 的核心是向量化和数据框（data.frame）。Bioconductor 提供统一的矩阵容器（SummarizedExperiment），DESeq2、edgeR 都基于它。

核心代码模式

# 安装和加载 Bioconductor 包
if (!requireNamespace("BiocManager", quietly = TRUE))
    install.packages("BiocManager")
BiocManager::install("DESeq2")
library(DESeq2)

# 读入表达矩阵（行=基因，列=样本）
countData <- read.csv("counts.csv", row.names = 1)
colData <- read.csv("samples.csv")

# 构建 DESeq2 对象并做差异表达
dds <- DESeqDataSetFromMatrix(countData = countData,
                              colData = colData,
                              design = ~ condition)
dds <- DESeq(dds)
res <- results(dds)
R 的 data.frame 像 Excel 表，但每一列可以是不同类型（数字、文本、因子）。Bioconductor 在其上加了"生物语义"：行是基因，列是样本，还有注释信息。
R 数据框解剖：点按钮看 countData 和 colData 如何合并成 DESeq2 对象

DESeq2 流程三步走：① DESeqDataSetFromMatrix（数据+设计公式）→ ② DESeq()（标准化+统计）→ ③ results()（提取差异基因）。

实战：自动化处理 100 个样本

用一个 Python 脚本批量处理 100 个 FASTQ 文件：读文件名、跑质控、调用比对工具、收集结果——这就是"生信流程"的雏形。

流程自动化模式

import subprocess
from pathlib import Path

fastq_dir = Path("data")
for fastq in fastq_dir.glob("*.fq.gz"):
    sample = fastq.stem.replace(".fq", "")
    output = f"results/{sample}.bam"

    # 调用命令行工具（BWA + samtools）
    cmd = f"bwa mem ref.fa {fastq} | samtools sort -o {output}"
    subprocess.run(cmd, shell=True, check=True)
    print(f"Done: {sample}")
这段代码是"自动流水线"：机械臂（Python）抓取零件（FASTQ），放到机床（BWA）加工，再放到下一个工位（samtools）。你只需要写一次，就能 7×24 小时跑。
流程模拟器：看 Python 脚本如何批量调度 5 个样本（点击"运行"启动）

进阶：Snakemake 流程管理

当流程变复杂（10+ 步骤、依赖关系交错），用 Snakemake 或 Nextflow 来管理：定义规则、自动调度、并行执行、断点续跑。

自己写脚本适合探索性分析；生产环境（重复跑、要给同事用）务必用 Snakemake/Nextflow，保证可复现、可维护。

你要跑一个 20 步的分析流程，中途第 10 步失败了，修改后想从断点继续而不是从头跑，用什么工具最合适？

自动化是生信工程师和"跑命令的人"的分水岭。学会写循环 + 调命令行 + 管理流程，你就升级了。

数据可视化：让数据说话

Python 的 matplotlib/seaborn 和 R 的 ggplot2 是生信可视化的双雄。选对图层和几何对象，就能把枯燥的表格变成有洞察的图。

火山图是"差异表达的标准照"：X 轴是变化倍数（往左降，往右升），Y 轴是显著性（越高越显著）。右上和左上角的点，就是你要关注的基因。
ggplot2 的哲学：图形 = 数据 + 映射（aes）+ 几何对象（geom）。理解这三层，就能自由组合出任何图。

调试与最佳实践

代码报错不可怕，可怕的是不知道哪里错了。掌握调试技巧和工程规范，让你的代码从"能跑"变成"可靠"。

常见错误类型

错误示例解决思路
语法错误漏了冒号/括号看 traceback 最后一行，检查该行
索引越界序列长度 100，取了第 101 位检查循环边界，用 len() 验证
类型错误把字符串当数字加print(type(x)) 确认类型
文件不存在路径写错用 os.path.exists() 检查
逻辑错误代码能跑但结果不对用 assert 或打印中间值验证

工程最佳实践

  • 版本控制：用 Git 管理代码，每次改动都写 commit message
  • 虚拟环境：Conda/venv 隔离项目依赖，避免"在我电脑上能跑"
  • 参数外置：把路径、阈值写在配置文件（YAML），不要硬编码
  • 日志记录：用 logging 模块记录关键步骤，方便回溯
  • 单元测试：对核心函数写 test，改动后自动验证
