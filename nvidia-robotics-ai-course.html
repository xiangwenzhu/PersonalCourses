第 1 章 · GPU：不是更快的 CPU，而是更宽的 CPU

GPU 用几千个简单核心换"同时处理海量数据"的吞吐量；深度学习恰好就是这种活。

很多人第一次看到 GPU 的参数会以为它是一颗"加强版 CPU"：核心更多、频率更高、所以更快。其实恰好相反——GPU 的每个核心通常比 CPU 核心更简单、更慢，单看"跑完一件事"的延迟，它往往打不过 CPU。

真正的区别在目标：CPU 优化的是延迟（一件事多快做完），GPU 优化的是吞吐（单位时间做完多少件事）。

CPUGPU
核心数量几十个，每个都很强成千上万个，每个较简单
擅长复杂分支、前后依赖的逻辑同样的操作作用在海量数据上
典型任务操作系统、数据库、单个请求矩阵乘法、卷积、图形渲染
优化目标延迟（Latency）吞吐（Throughput）

神经网络里 90% 以上的计算是矩阵乘法和卷积。它们的共同点是：每个输出元素的计算彼此独立，可以切成几百万份同时做。这正是 GPU 的主场。

餐厅后厨：CPU 是 8 位全能大厨，能独自完成一道复杂菜；GPU 是 2000 个帮厨，只会切菜，但可以同时开切。训练神经网络，本质上是"切十亿刀土豆"。

但 GPU 不是万能的

GPU 有两个天生的"软肋"：

  • 启动开销：把任务从 CPU 交给 GPU、启动成千上万个线程、再同步结果，本身有固定成本。任务太小时，这点开销会吃掉全部收益。
  • 怕分支：GPU 以 32 个线程为一组（warp）执行同一条指令，如果组内线程走不同的 if 分支，就得排队分别执行。
英伟达 H100 有 132 个 SM、约 1.7 万个 FP32 运算单元，FP16 张量算力接近 1000 TFLOPS（每秒一千万亿次运算）。同代的顶级 CPU 只有几十个核心、几 TFLOPS。差距来自"宽度"，不是"速度"。
拖一拖：任务多大时，GPU 才值得出手？

GPU 的强项不是"单线程更快"，而是"把同一件事复制几万份同时做"。任务越规整、越能并行，GPU 越占优；逻辑越复杂、依赖越多，CPU 越合适。

第 3 章 · 拆开 GPU：车间、班组与仓库

GPU = 很多车间（SM），每个车间按 32 人一组（warp）同步干活，工具放手边（寄存器），材料从仓库（显存）搬。

要理解 CUDA 程序为什么快或慢，得先认识 GPU 的物理结构。下面这套类比会贯穿整门课。

GPU 是一座工业园：SM 是一间车间；warp 是 32 个动作整齐划一的工人；寄存器 是每人手边的小工具盒；共享内存 是车间中央的白板；L2 缓存 是园区仓库；HBM 显存 是城外的大货仓。
点击卡片，认识六个关键词
SM
Streaming Multiprocessor，GPU 的基本计算车间。H100 有 132 个，每个含 FP32 单元、Tensor Core、调度器和共享内存。
CUDA Core
一个 FP32 运算通道。注意它不是独立处理器，只是 SM 里众多运算单元之一。
Warp
32 个线程组成的调度单位。同一 warp 执行同一条指令、处理不同数据（SIMT）。
寄存器
每个线程私有，速度最快但数量有限。寄存器用得多，SM 能同时驻留的线程就少。
共享内存
同一个 block 内的线程共享，需要程序员手动管理，用来做数据复用（tiling）。
HBM 显存
容量大、带宽高（H100 约 80GB、3.35TB/s），但延迟比寄存器高几百倍，是多数 kernel 的瓶颈来源。

一张表看懂"存储金字塔"

层级谁可见典型容量延迟量级谁管理
寄存器单个线程每 SM 256KB约 1 个周期编译器
共享内存 / L1同一个 block每 SM 约 228KB（H100）二三十个周期程序员 + 硬件
L2 缓存整张 GPU几十 MB约 200 个周期硬件

以上为 Hopper 一代量级，仅用于建立直觉；不同架构数字有差异。

占用率（occupancy）是这里最实用的概念：一个 SM 最多同时驻留 64 个 warp（H100），实际驻留比例就是占用率。占用率太低，车间里工人太少，掩盖不了访问显存的延迟；但盲目堆线程也可能因为寄存器不够而适得其反。

GPU 性能问题十有八九是两句话：数据没喂饱（带宽受限）或线程没排满（占用率低）。第 6、7 章会把这两件事量化。
先记住层级：线程 → warp（32）→ block → grid；存储：寄存器 → 共享内存 → L2 → HBM。之后看到任何 CUDA 优化技巧，都能归到"减少搬运"或"提高并行"两类。

第 4 章 · CUDA：写一个线程，复制一万份

CUDA 的编程模型只有三个关键词：grid、block、thread。你只写"一个线程做什么"，GPU 负责把它复制到成千上万个线程上。

CUDA 不是一门新语言，而是 C/C++ 的一套扩展：你写一个普通函数，加上 __global__ 标记，它就变成了能在 GPU 上被大量线程同时执行的 kernel。

// 每个线程算一个元素：c[i] = a[i] + b[i]
__global__ void vecAdd(const float* a, const float* b, float* c, int n) {
    int i = blockIdx.x * blockDim.x + threadIdx.x;  // 全局线程编号
    if (i < n) c[i] = a[i] + b[i];                  // 边界检查
}

int main() {
    int n = 1 << 20, bytes = n * sizeof(float);
    float *d_a, *d_b, *d_c;
    cudaMalloc(&d_a, bytes);                          // 1. 显存分配
    cudaMemcpy(d_a, h_a, bytes, cudaMemcpyHostToDevice); // 2. 数据搬到 GPU
    vecAdd<<<(n + 255) / 256, 256>>>(d_a, d_b, d_c, n); // 3. 启动 kernel
    cudaMemcpy(h_c, d_c, bytes, cudaMemcpyDeviceToHost); // 4. 结果搬回
}

几个必须说清的概念：

  • host / device：CPU 侧叫 host，GPU 侧叫 device。两者有各自的内存，需要显式拷贝（统一内存可以简化，但不改变物理事实）。
  • grid / block：启动配置写成 <<<grid, block>>>。block 是线程的集合，grid 是 block 的集合。
  • threadIdx / blockIdx：线程在 block 内的编号、block 在 grid 内的编号，可以是一维、二维或三维。
  • warp：硬件实际以 32 个线程为单位调度。block 大小取 32 的倍数，能避免"半个 warp 空转"。
一个 CUDA 程序的四步走
第 1 步 · 分配：用 cudaMalloc 在显存里申请空间。显存和内存是两块独立的物理区域。
第 2 步 · 搬运：用 cudaMemcpy 把输入数据从内存拷到显存。这一步往往比计算还慢，所以要尽量批量、异步。
第 3 步 · 启动：写 <<<grid, block>>>。GPU 把 grid 切成一个个 block，分发到空闲的 SM 上执行。
第 4 步 · 回传：把结果拷回内存。若后续还有 kernel，就让数据留在显存里，别来回搬。

block 大小为什么重要？

假设矩阵有 256×256 个元素，每个线程算一个点。block 取 16×16 时，一共需要 16×16 = 256 个 block；block 取 32×32 时只需要 64 个 block。block 太小，warp 装不满；block 太大，调度粒度粗、尾部可能空转。

拖动滑块：block 尺寸如何切开矩阵、如何组成 warp

"线程开得越多越快"是错的。线程总数要刚好覆盖数据；多余的线程只做边界判断然后退出，仍然占用调度资源。真正决定速度的是访存模式与占用率。
CUDA 的心智模型：你写的是一份"单线程说明书"，GPU 把它复印几万份并发执行。grid/block 是逻辑排队，warp 才是物理执行单位。

第 6 章 · 算力、带宽与 Roofline：为什么 GPU 会"饿"

一块卡的实际性能上限由两条线决定：峰值算力（屋顶）和 带宽 × 算术强度（斜坡），取较小者。

厂商发布会只讲一个数字：TFLOPS。但真实程序很少跑到峰值，因为 GPU 要先把数据搬到计算单元旁边。搬得不够快，算力再高也只能干等。

第一步：算清"要做多少活"

两个 $N \times N$ 矩阵相乘，每个输出元素要做 $N$ 次乘法和 $N-1$ 次加法，共 $N^2$ 个输出元素，所以总计算量约为：

$$\text{FLOPs} \approx 2N^3$$

而至少要把两个矩阵读进来，数据量约为 $2N^2$ 个元素。定义算术强度（每搬 1 字节能算多少次）：

$$\text{AI} = \frac{\text{FLOPs}}{\text{Bytes}} = \frac{2N^3}{2N^2 \times b} = \frac{N}{b}$$

其中 $b$ 是每个元素占的字节数：FP32 为 4，FP16 为 2。

第二步：画 Roofline

可达性能为：

$$P = \min\left(P_{\text{peak}},\; B_{\text{mem}} \times \text{AI}\right)$$

$P_{\text{peak}}$ 是峰值算力，$B_{\text{mem}}$ 是显存带宽。算术强度低时被带宽卡住（斜坡段），高时被算力卡住（屋顶段）。

以 H100 的 FP16 为例：$N=4096$ 时 AI $= 2048$ FLOP/Byte，带宽上限 $= 3.35\text{TB/s} \times 2048 \approx 6.9\text{PFLOPS}$，远高于 989 TFLOPS 的峰值——所以大矩阵乘法是算力受限。而逐元素加法这类操作 AI 只有个位数，几乎必然带宽受限。

Tensor Core 是英伟达从 Volta 开始加入的专用矩阵单元：一条指令完成一个小矩阵的乘加（如 $16\times8\times16$），FP16 输入、FP32 累加，后来扩展到 BF16、FP8，Blackwell 还支持 FP4（主要用于推理）。它把"屋顶"抬高了一个数量级，但也让"喂数据"变得更难。

调矩阵大小与精度，看工作点落在屋顶还是斜坡

"峰值 TFLOPS"是理想条件下的数字：往往要求特定精度、特定矩阵形状、甚至开启稀疏加速。真实训练里常用的指标是 MFU（模型算力利用率），大模型训练能到 30%–50% 已属不错。
看到任何"这卡多少 TFLOPS"的说法，都追问三件事：什么精度？带宽多少？我的负载算术强度是多少？ 这三个数决定实际性能，而不是单一峰值。

第 7 章 · 写对 kernel 的三件事：索引、合并访存、占用率

同样一次矩阵乘，写法不同性能可以差十倍；瓶颈通常不是"算得慢"，而是"等数据"。

① 索引：每个线程找对自己的数据

最常见的一维写法是 i = blockIdx.x * blockDim.x + threadIdx.x。二维矩阵则用两个维度分别算行、列。索引错了不会报错，只会算出莫名其妙的结果——所以一定要做边界检查。

② 合并访存：让 32 个线程读连续的地址

显存是按"事务"读的。一个 warp 的 32 个线程如果访问连续地址，硬件能用一次 128 字节事务搞定；如果地址乱跳，就可能拆成 32 次事务，带宽利用率掉到几十分之一。

合并访存像快递驿站：32 个包裹在同一个货架上，一次就能全拿；如果散落在 32 个仓库，就得跑 32 趟。计算单元再快，也架不住这样跑腿。

③ 占用率：车间里同时有多少工人

占用率 = 一个 SM 上实际驻留的 warp 数 ÷ 上限（H100 为 64）。它由三样东西共同限制：

  • block 大小：线程数必须是 32 的倍数，且不超过 1024。
  • 每线程寄存器数：寄存器总量固定，单线程用得越多，能同时驻留的线程越少。
  • 每 block 共享内存：共享内存也是有限资源。
调 block 大小和寄存器用量，看占用率怎么变

共享内存分块：把"重复搬运"变成"搬一次用多次"

矩阵乘法里，每个输出元素都要读一整行和一整列。如果直接读显存，同样的数据会被重复搬运 $N$ 次。经典做法是让一个 block 先把一小块数据搬进共享内存，再在车间里反复使用：

__shared__ float As[TILE][TILE];
__shared__ float Bs[TILE][TILE];
// 每个线程负责搬运一小格，然后 __syncthreads()
for (int k = 0; k < N; k += TILE) {
    As[ty][tx] = A[row * N + k + tx];
    Bs[ty][tx] = B[(k + ty) * N + col];
    __syncthreads();
    for (int j = 0; j < TILE; j++)
        acc += As[ty][j] * Bs[j][tx];
    __syncthreads();
}

一个 warp 包含 个线程；一个 block 的线程数上限是 。

优化 kernel 的顺序：先保证索引正确 → 再看访存是否合并 → 再调 block 大小与寄存器 → 最后才考虑共享内存分块等高级技巧。顺序反了，往往是在优化一个不是瓶颈的地方。

第 8 章 · 在仿真里练一万次：Isaac Lab 与 sim2real

真实机器人摔一次很贵，仿真里可以同时开几千个"平行世界"，一晚上练完人类几年的经验。

机器人策略训练本质是一个循环：策略网络看当前观测（关节角度、IMU、相机），输出动作（目标关节位置或力矩），物理引擎算出下一时刻的状态和奖励，然后更新网络。

如果只有一个环境，这个循环慢得没法用。Isaac Lab 的关键设计是：把几千个环境同时放在一张 GPU 上跑，物理计算、观测拼接、策略推理全部留在显存里，避免 CPU 与 GPU 之间来回搬数据。

PPO：最常用的"练习方法"

近端策略优化（PPO）通过"采集一批经验 → 计算优势 → 限制每次更新的幅度"来稳定训练。你不需要手写它，Isaac Lab 已集成 RSL-RL、skrl、Stable-Baselines3 等实现。真正花时间的是奖励设计：走快了奖励、摔倒了惩罚、偏离方向扣分、抖动扣分……

sim2real：仿真里会走，真机上未必

仿真与现实的差距（sim2real gap）主要来自三处：

  • 接触模型：摩擦、弹性、地面材质难以精确建模。
  • 执行器：真实电机的延迟、死区、温漂，仿真里往往过于理想。
  • 感知：相机噪声、光照变化、传感器延迟。

最常用的对策是域随机化：训练时随机改变质量、摩擦系数、电机延迟、光照、纹理，让策略"见过各种世界"，从而对真实世界更鲁棒。代价是仿真内的成绩会下降——这是正常的。

第 9 章 · 数字孪生与合成数据：Omniverse、Replicator、Cosmos

当真实数据又贵又少，就用"可编程的世界"造数据——但关键不是数量，而是分布覆盖。

机器人数据比图像数据更难搞：要有人真的去推、去抓、去摔，还要标注位姿和动作。于是英伟达把重心放在"造世界"上。

Omniverse：用 USD 描述世界

OpenUSD 是一种场景描述格式，把几何、材质、光照、物理属性、动画都组织成可组合的图层。Omniverse 基于 USD 做实时协作与渲染，多个工具可以同时编辑同一个场景。机器人仿真需要的"数字孪生"，就是这样一个与真实工厂/房间对应的虚拟场景。

Isaac Sim 与 Replicator：带标签地量产图像

Isaac Sim 在 Omniverse 上提供机器人、传感器（RGB 相机、深度相机、激光雷达、IMU）和 PhysX 物理。Replicator 则负责程序化生成：随机摆放物体、随机材质与光照、随机相机位姿，同时自动输出分割掩码、深度图、边界框、6D 位姿等标注。这些标注在真实数据里往往要靠人工标几天。

Cosmos：世界基础模型

Cosmos 系列世界基础模型（WFM）用大量视频训练，能生成或预测符合物理直觉的视频。用途包括：把仿真画面"翻译"得更像真实相机、生成罕见场景、评估策略在未见过场景下的表现。Cosmos Reason 这类视觉语言模型还能对物理场景做常识推理。

随机化越强，合成数据能覆盖多少真实场景？

蓝点为真实场景在特征空间中的分布，橙点为合成数据；覆盖率为示意计算，用于说明"分布覆盖"这一概念。

"合成数据越多越好"是典型误区。如果合成数据的分布不覆盖真实情况（比如只在一个固定光照下渲染），数量再多也只是在重复同一种偏差。分布覆盖、物理一致性、标注准确性，比单纯堆量重要得多。
想一想：如果真实工厂里有一种仿真中从未出现的反光地面，你该怎么办？

三条路可以组合：① 在仿真里加入各向异性材质与随机反射的域随机化；② 用真实相机拍几张该地面，做神经重建（如 NuRec）把真实场景搬进仿真；③ 采集少量该场景的真机数据做微调。单靠"多生成一些数据"解决不了分布缺口。

合成数据的价值 = 覆盖度 × 标注质量 × 物理一致性。Omniverse 提供场景，Isaac Sim 提供物理与传感器，Replicator 提供批量标注，Cosmos 提供生成与评估——四者合起来才是一条完整的数据生产线。

第 10 章 · GR00T、Thor 与工程选型

机器人基础模型把"看懂—想清楚—动起来"塞进一个网络；而它最终要跑在机器人身上一块几十瓦到一百多瓦的芯片上。

GR00T：给类人机器人用的基础模型

GR00T N1 是英伟达在 2025 年发布的开放权重机器人基础模型。它采用双系统结构：

  • System 2（慢思考）：视觉语言模型，理解"把红色积木放进盒子"这类指令和场景，输出中间表示。
  • System 1（快执行）：扩散 Transformer，根据中间表示和当前观测，一次生成一小段动作序列，频率足以做实时控制。

训练数据来自四类来源：真机遥操作轨迹、人类第一视角视频、Isaac 合成的仿真数据、互联网图文与视频。模型开放权重，目的是让开发者用自己的机器人数据做后训练（post-training），适配不同本体。

从训练到部署：模型要"瘦身"

机器人的控制频率常见几十 Hz 到 100+ Hz，意味着每 10–30 毫秒就要出一次动作。部署链条通常是：

  1. 在数据中心用多卡训练 / 微调；
  2. 用 TensorRT 做算子融合、量化（FP16 / FP8 / INT8），生成针对目标芯片的引擎；
  3. 在 Jetson 上运行推理，配合 Isaac ROS 的视觉、定位、建图模块；
  4. 加安全层：限位、力矩上限、急停、异常检测。

四个常见误区：
① "GPU 越大越好"——要看带宽、互联、利用率和成本，训练与推理的需求完全不同。
② "Jetson 也能训练大模型"——Jetson 主要做推理，训练仍在数据中心。
③ "仿真做好了就能直接上真机"——仍需真机校准、安全兜底与少量微调。
④ "机器人基础模型拿来即用"——不同本体的关节数、尺寸、动力学差异很大，通常都要后训练。
