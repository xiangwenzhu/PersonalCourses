RNA-seq 实战：从原始数据到差异表达

RNA-seq 是什么

RNA-seq 测的是"基因的表达量"：把细胞里的 mRNA 反转录成 cDNA 再测序，数每个基因有多少条 reads 落在上面。

DNA 是"图纸"，RNA 是"正在生产的产品清单"。RNA-seq 就是给这个清单拍照：哪个基因转录得多（表达高），哪个转录得少（表达低）。

DNA-seq 像查图书馆藏书（有什么书），RNA-seq 像查借阅记录（哪些书正被大量借阅）。借阅量 = 表达量。

核心概念速览

点击卡片，记住 4 个核心概念
Read count
比对到某基因上的 reads 数，是表达量的原始度量。但受基因长度和测序深度影响，不能直接比。
FPKM/RPKM
Fragments Per Kilobase per Million：校正了基因长度和测序深度的表达量，可跨样本比。
TPM
Transcripts Per Million：另一种标准化，样本间总和恒定（100万），比 FPKM 更适合跨样本比较。
Fold change
倍数变化：处理组表达 / 对照组表达。log2FC = 1 表示 2 倍上调，-1 表示 2 倍下调。
RNA-seq 回答的问题：在不同条件（疾病 vs 健康、处理 vs 对照）下，哪些基因的表达发生了显著变化？

RNA-seq 与 DNA-seq 的核心区别是什么？

理解"reads 数 → 表达量"的转换，是 RNA-seq 分析的第一步。接下来：数据怎么从 FASTQ 变成表达矩阵。

分析流程：六步走到表达矩阵

标准 RNA-seq 流程：质控 → 去接头 → 比对 → 定量 → 合并 → 差异表达。每一步都有对应工具，像流水线一样自动跑。

动手排一排：RNA-seq 分析的正确顺序
比对到参考基因组（HISAT2/STAR）
原始数据质控（FastQC）
差异表达分析（DESeq2）
表达定量（featureCounts/StringTie）
去除接头和低质量（fastp/Trimmomatic）
合并所有样本的表达矩阵

常用工具组合

步骤工具输出
质控FastQC + fastpHTML 报告 + cleaned FASTQ
比对HISAT2 / STARSAM/BAM（含比对坐标）
定量featureCounts基因 × 样本的 count 矩阵
差异表达DESeq2 / edgeR差异基因列表（含 log2FC, p, FDR）
RNA-seq 分析像洗车：冲水（质控）、打泡沫（去接头）、刷洗（比对）、冲净（定量）、擦干（合并）、上蜡（差异分析）。每道工序都有专用工具。
比对到基因组后，一条 read 可能跨外显子（CIGAR 中的 N），所以比对工具（STAR）和定量工具（featureCounts）要配合处理剪接。

为什么 RNA-seq 比对工具（如 STAR）需要特别处理"跨外显子的 reads"，而 DNA-seq 比对工具不需要？

记住这个流程，你就有了 RNA-seq 的"地图"。接下来深入每一步的关键参数和陷阱。

质控与比对：细节决定成败

FastQC 看数据质量，fastp 做清理；比对率 >70% 才算合格， <50% 要怀疑参考基因组选错或样本污染。

FastQC 关键指标

  • Per base sequence quality：每个位置的平均质量，通常 5' 端高，3' 端低（测序衰减）
  • Adapter content：接头污染比例，>5% 需要去接头
  • Sequence duplication：重复序列比例，过高提示 PCR bias 或文库复杂度低
比对质量诊断：滑块调整参数，看比对率如何变化

比对率突然暴跌？常见原因：① 参考基因组版本不对（hg19 vs hg38）② 样本污染（人源样本混了细菌）③ 接头没去除，干扰比对。
STAR 比 HISAT2 更准但内存大（人类基因组需 30GB+ RAM）；HISAT2 更快更省内存，适合资源有限时。

比对后你发现比对率只有 40%，最不可能的原因是什么？

质控和比对是"地基"，这一步没做好，后面的差异表达全是空中楼阁。多花 10 分钟看报告，省得后面返工。

定量：从 BAM 到表达矩阵

featureCounts 数每个基因有多少 reads 覆盖，输出 count 矩阵（行=基因，列=样本）。这是差异表达的输入。

featureCounts 的核心逻辑

# 对每个样本的 BAM 文件计数
featureCounts -a annotation.gtf \
              -o counts.txt \
              -t exon \
              -g gene_id \
              sample1.bam sample2.bam sample3.bam
Read 计数模拟器：点击"计数"看 reads 如何被分配到基因

计数中的边界情况

  • 多重比对（multi-mapping）：一条 read 比对到多个位置，默认丢弃或按比例分配
  • 跨外显子 reads：只算一次，归到该基因
  • 基因重叠：两个基因有重叠区域，featureCounts 默认跳过 ambiguous reads
Count 矩阵是整数（0, 1, 2, 3...），不能直接取 log 或标准化。后续 DESeq2 会用负二项分布模型处理。

一条 read 同时落在 GeneA 和 GeneB 的重叠区，featureCounts 默认会怎么处理？

定量是"数数"，但要数得准：处理好多重比对、剪接、基因重叠，才能得到可靠的表达矩阵。

差异表达：DESeq2 的统计魔法

DESeq2 用负二项分布建模基因表达，通过标准化 → 离散度估计 → Wald 检验，找出处理 vs 对照的显著差异基因。

DESeq2 三步走

DESeq2 内部流程
① 标准化（Size factor）：计算每个样本的"测序深度校正系数"，让样本间可比。
② 离散度估计（Dispersion）：估计每个基因的生物学变异程度（重复样本间的波动）。
③ Wald 检验：对每个基因检验"处理效应是否为 0"，输出 p 值和 log2FC。
④ 多重检验校正：2 万个基因同时检验，用 BH 法控制 FDR（假发现率）。
DESeq2 像"严格的裁判"：不仅看处理组和对照组的平均值差多少（log2FC），还看组内重复样本的波动（离散度）。波动小 → 容易显著；波动大 → 即使均值差大也可能不显著。
离散度演示：拖动滑块看组内变异如何影响显著性

输出结果解读：padj < 0.05 且 |log2FC| > 1（即 2 倍变化）通常作为筛选阈值。

不要只看 p 值！必须同时看 log2FC 和 baseMean（平均表达量）。低表达基因的 p 值可能假显著。

两个基因 log2FC 都是 2，但 GeneA 的 p=0.001，GeneB 的 p=0.2。最可能的解释是？

DESeq2 是 RNA-seq 差异表达的金标准。理解"离散度"这个概念，你就能看懂为什么有些"看起来差异大"的基因并不显著。
