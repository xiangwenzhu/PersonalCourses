大模型微调 · 第 1 课：微调的直觉与决策

预训练 vs 微调：能力从哪来

微调不是"造一个新模型"，而是拿一个已经读完整个互联网的"通才"，用你自己的教材再教它一门手艺——底座能力来自预训练，领域技能来自微调。

你大概率用过那种"什么都能聊两句"的大模型。它为什么能写诗、写代码、还会翻译？因为在见到你之前，它经历过一个叫预训练（pre-training）的阶段：把海量的文本（网页、书籍、代码……）通读一遍，学会了"下一个词大概是什么"这个游戏。玩着玩着，它顺便学会了语法、常识、推理的基本套路。

但通才有个问题：它什么都懂一点，却不精通你的业务。它不知道你公司的退货政策，不懂你行业的黑话，写不出你家客服的口吻。这时候就轮到微调（fine-tuning）登场了。

把大模型想象成一位名校毕业生：预训练 = 从小学到大学的通识教育，让他博览群书、谈吐得体；微调 = 入职后的岗位培训，用公司的内部手册、优秀工单案例，把他教成"像我们人一样说话做事"的员工。通识教育决定他的底子有多好，入职培训决定他上岗后能干什么活。
微调改的是模型的"权重"（模型内部那几千亿个可调旋钮的数值）。训练完成后，这些旋钮记住了你的数据风格，模型就"学会"了。这就是为什么微调后的模型不再需要每次把说明书塞进对话框——知识已经"长"在模型里了。
翻卡：这些词到底什么意思？
预训练
用海量通用文本训练模型，让它学会语言与世界知识。贵（算力）、慢（数月）、一次性，由大厂完成。
微调
在预训练好的模型上，用你自己的小规模数据继续训练，让模型适应特定任务或风格。
权重
模型内部存储"学到的知识"的数值参数。微调本质上就是微调这些数值。
底座模型
预训练完成、尚未针对任何业务调整的模型，是后续一切定制化的起点。

一个模型"读过整个互联网、什么话题都能聊"，这是在描述哪个阶段？

预训练给模型"通识底子和语言能力"，微调给模型"你的领域技能和说话风格"。微调不是从零开始，而是站在巨人的肩膀上补课。

为什么微调：能做什么，不能做什么

微调的上限由你的数据决定：数据教不会的，微调也变不出来。它能改变模型的行为、风格和领域习惯，却不能凭空注入事实知识。

很多人第一次微调时最惊讶的发现是：微调改变的是"行为"，不是"知识库"。如果你的训练数据里全是优质客服对话，微调后模型会变得像客服一样说话——用词、语气、回答结构都对。但如果你从没教过它"30 天内可以退货"，它答不出这条政策。

为什么？因为微调数据的量级通常是几千到几十万条，而预训练数据是万亿词级别。想靠微调"记住"大量新事实，就像指望入职培训三天让人背下百科全书——教的是套路，不是百科全书。

微调擅长（✅）微调不擅长（❌）
学会特定输出格式（JSON、固定话术、代码风格）注入大量精确事实（产品价目表、最新新闻）
模仿特定语气与领域黑话让模型知道训练截止日之后发生的事
把"会但不稳定"的能力变稳定（按你的要求作答）根治幻觉（模型一本正经地胡说八道）
教会明确的判断边界（什么该拒绝、什么该转人工）数据本身有偏见时，模型会把偏见学得更牢
入职培训能教新员工"怎么接待客户、按什么流程走、用什么语气"，但不可能三天内让他背下公司三十年的产品手册。查手册是培训之外的事——这对应后面要讲的 RAG（检索增强生成）。

你的目标是让模型回答时永远输出严格合法的 JSON 格式（方便程序解析）。微调能做到吗？

想让模型记住公司最新发布的 500 页产品手册并准确回答其中的细节，微调是最佳选择吗？

判断口诀：要"怎么做"，找微调；要"知道什么"，找检索。风格、格式、行为边界 → 微调；事实、最新资料、可溯源知识 → RAG。

微调 vs Prompt vs RAG：决策树

定制一个大模型有三条路：改提示词（Prompt）、外挂知识库（RAG）、动模型本身（微调）。选路的判断标准只有两条：你要改的是"行为"还是"知识"，以及你愿意付出多少成本。

先认识三个术语（后面会一直用）：

  • Prompt Engineering（提示词工程）：不改模型，只优化你发给模型的指令。成本几乎为零，但知识依然依赖模型自己"记得"。
  • RAG（Retrieval-Augmented Generation，检索增强生成）：不改模型，回答前先从你的知识库检索相关资料，连同问题一起发给模型。知识可更新、可溯源，但多一步检索，有延迟。
  • 微调（Fine-tuning）：改模型权重，把行为模式"焊"进模型里。响应快、风格稳定，但知识会过时，训练要花算力和数据。

三条路并不互斥，成熟系统常常是组合拳：RAG 提供最新知识，微调稳定行为与格式，Prompt 负责临门一脚的指令。
决策口诀：行为问题找微调，知识问题找 RAG，两者都不急就先写好 Prompt。成本从低到高：Prompt → RAG → LoRA/QLoRA → 全量微调。

显存直觉：参数、精度与显存

模型在 GPU 显存里占多大地方，基本由两个数决定：参数量 × 每个参数用几个字节。精度砍一半，显存近乎砍半——这就是后面 QLoRA 省显存的根基。

GPU 显存（video memory）是训练大模型时最紧俏的资源。要估它占多少，先搞清三件事：

  • 参数量：模型里"旋钮"的个数。7B 就是 70 亿个（B = billion，十亿）。
  • 精度（precision）：每个参数用多少位二进制存储。常用两档：FP16（16 位，2 字节）和 FP32（32 位，4 字节）。
  • 换算：显存 ≈ 参数量 × 每参数字节数。7B × 2 字节 ≈ 14 GB，这还没算训练和推理的其他开销。

精度低一半，数值范围变小、精度略降，但显存直接减半。省显存的思路几乎都是围绕"用更低精度存东西"展开的：

技术做什么大致省多少
FP16 / BF16 训练参数和计算都用 16 位参数显存减半
8bit / 4bit 量化（Quantization）参数压到 8 位甚至 4 位存储参数显存缩到 1/2 ~ 1/4（估算，实际略多）
LoRA只训练新增的小矩阵，不更新全部参数梯度与优化器状态大幅减少（后续课展开）
这张表里的数字是"参数本身"的显存。真正训练时还要放梯度、优化器状态、激活值，第 5 章会算这笔总账。量化到 4bit 后参数显存约为原来的 1/4，是估算口径（工程上还有少量额外开销）。

全量微调的显存总账

全量微调时，显存里要同时放四样东西：参数、梯度、优化器状态、激活值。前三样按参数量线性增长，其中 Adam 优化器一份就要占 2 倍参数字节——这就是为什么全量微调贵得离谱。

用 Adam（最常用的优化器）做一次全量微调，每个参数要存：

  • 参数本身：FP16 存，2 字节
  • 梯度（gradient）：模型对"答得对不对"的反馈信号，每个参数一份，FP16，2 字节
  • 优化器状态：Adam 为每个参数维护两个滑动平均量（常叫"一阶矩、二阶矩"），通常用 FP32 存，4+4=8 字节

于是每个参数的"静态开销"合计 12 字节：2（参数）+ 2（梯度）+ 8（Adam 状态）。再叠加上随序列长度和 batch 变化的"激活值"（中间计算结果），总显存大致为：

$$\text{显存} \approx P \times 12\ \text{字节} + \text{激活值}$$

其中 $P$ 是参数量。代入 7B：静态部分就是 70 亿 × 12 字节 ≈ 84 GB，还没算激活值——单张消费级显卡（24 GB）根本放不下，这就是全量微调的门槛。

省显存的两条主路线：把"每参数 12 字节"降下来（如梯度检查点省激活值、8bit Adam 省优化器状态），或干脆不全量训练——只训练少量新增参数（LoRA 一族）。第 7 章的综合案例会用到这个判断。

用 Adam 全量微调时，"优化器状态"大约是参数本身（FP16 存）的多少倍显存？

7B 模型全量微调，静态显存（参数+梯度+Adam 状态）约为 84 GB。下面哪种做法不能降低这笔账？

以上 12 字节/参数是混合精度训练的常见简化口径，不同框架会略有出入（比如有的实现把主权重也存 FP32）。重点是数量级直觉，不要记死某个精确数字。
全量微调显存账：每参数 ≈ 12 字节（FP16 参数 + FP16 梯度 + 2×FP32 Adam 状态）+ 激活值。7B ≈ 84 GB 起步——下一个问题自然是：能不能不全量训？

灾难性遗忘与缓解

模型学新东西时会把旧的冲掉——这叫灾难性遗忘。学得越狠（学习率越高、数据越偏），忘得越多；缓解的思路是让新数据里"掺旧"（回放）或给重要参数"上锁"（EWC）。

微调有个经典副作用：你用一万条医疗问答把模型训得很专业，回头发现它连"1+1=2"都开始答错。灾难性遗忘（Catastrophic Forgetting）指的是：模型适应新任务时，冲掉了原来学到的能力。

为什么会这样？训练本质上是"按新数据调旋钮"。如果新数据和旧能力依赖同一批旋钮，调过头了旧能力就没了。两个旋钮决定遗忘程度：学习率（每步调多大）和训练数据的相关性（新任务离原能力多远、多窄）。

遗忘模拟器：拖滑块，看"新能力"涨、"旧能力"怎么掉

两条经典的缓解路线（知道思路即可，本系列后续不深究公式）：

  • 经验回放（Replay）：训练新任务时混进一部分旧任务数据，让模型"温故知新"。朴素但极其有效，工程上最常用。
  • 弹性权重巩固（EWC）：给"对旧任务重要"的参数加保护，训练新任务时不许大改它们（像给关键旋钮上锁）。更优雅，但更复杂。
学新东西就像往一杯满水里倒颜料：倒得越猛（学习率高）、颜料和原来的水越不相容（任务差得远），原来的水被染得越厉害。经验回放 = 不断补些原来的水；EWC = 先把最重要的那部分水冻住。

哪种情况最容易引发灾难性遗忘？

遗忘不是微调的 bug，是训练的物理。实战口诀：学习率宁小勿大，数据里掺旧，训完测一遍旧能力。后面学 LoRA 时你会发现，只动少量参数本身就是天然的"防遗忘锁"。

综合案例：客服问答选型实战

真实业务 rarely 单选：一个客服机器人往往要"RAG 供知识 + 微调稳行为 + Prompt 控流程"。但预算和算力有限时，总得排出优先级——这就是选型。

考虑一个典型场景：给一家电商公司做售后问答机器人。需求清单看着很普通：能准确引用退换货政策（知识）、用公司规定的口吻和格式（行为）、回答要快（延迟）、别太贵（预算）、政策每月都改（更新频率）。

这个案例的最优解通常是组合方案：RAG 负责政策知识（可更新、可溯源） + LoRA 微调稳定口吻与拒答边界（行为固化） + Prompt 定义回答流程。单独任何一条路都不够用。
情景选择器：三个业务场景，你会怎么选？

每个场景先自己判断，再点开参考答案对照。

场景 A：把模型输出的 SQL 查询准确率从 80% 提到 95%（Text-to-SQL） 参考方案：LoRA/QLoRA 微调（+ 少量高质量示例），Prompt 辅助。
理由：SQL 语法是稳定的"行为/能力"问题，不是频繁更新的知识问题；几百到几千条"问题→正确 SQL"的样本微调即可显著提升。RAG 帮不上语法本身的忙。注意训练数据要覆盖各种问法，避免微调后只会见过的句式。
场景 B：法律助手必须逐条引用最新法规条文，且法规库每周更新 参考方案：RAG 为主，Prompt 规定引用格式。
理由："最新、可溯源、高频更新"是 RAG 的三个关键词，微调在这里全踩反：知识会过时、无法逐条溯源、每次更新都要重训。若还希望它用法律文书的规范口吻，可以再叠加一次 LoRA 微调稳定风格。
场景 C：让 7B 开源模型学会公司的 50 条客服话术（固定格式 + 拒答规则），团队只有一张 24GB 消费级显卡 参考方案：QLoRA 微调。
理由：行为固化是微调主场；而 24GB 显存放不下全量微调（静态账就约 84GB），QLoRA 用 4bit 加载底座 + 只训练少量参数，正是为这种预算设计的方案——这也是本系列第 2 课的主角。

动手前清单与 GPU 选择

动手微调前，先回答五个问题（数据够吗？值得吗？装得下吗？测什么？跑多久？），再用"微调选型决策器"过一遍你的真实约束。

动手前：五步检查
① 数据检查：我有多少条高质量样本？格式统一吗？有没有标注错误？（回想 L1：垃圾进，垃圾出。）
② 必要性检查：这个问题真的需要微调吗？写好 Prompt、加 RAG 是否已解决 80%？（成本：Prompt ≪ RAG ≪ LoRA ≪ 全量）
③ 显存检查：按"每参数 12 字节"估算全量微调；装不下就选 LoRA/QLoRA，算出大致所需的显存。
④ 评估检查：用什么指标判断微调成功？准备一份不参与训练的测试集（test set），训前训后各测一遍。
⑤ 防遗忘检查：通用能力会不会退化？测试集里要包含一些通用问题，训完对比答对率。

GPU 怎么选（粗略口径，非报价）
